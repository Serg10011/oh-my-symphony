# Версионированные скрипты досок

Исходники скриптов хранятся в `ours/projects/<комплект>/`. Установленными
копиями в папках досок управляет `ours/bin/project-update` (S4-30).
Сейчас описан комплект `eve`; для следующего проекта нужен свой комплект,
а не копирование файлов EVE. Настройки проекта по-прежнему принадлежат
его `project.toml`; `project-render` собирает из них общие конфигурации
и промпты. `post-merge` сохраняет прежнюю область ответственности.

## Обычный порядок

Команды ниже выполняются Python служебной копии Symphony. Слияние и
применение к работающей среде требуют принятого решения Сергея.

Просмотреть установленную и доступную версии без записи файлов:

```bash
/Users/helloworld10011/dev/oh-my-symphony/.venv/bin/python /Users/helloworld10011/dev/oh-my-symphony/ours/bin/project-update eve
```

`--diff` добавляет текстовый дифф. Источник по умолчанию — `HEAD` репозитория,
из которого запущена команда: файлы берутся из Git-объектов, а не из
незакоммиченной рабочей папки. Версия комплекта — SHA-256 его описания,
содержимого и прав файлов; коммит источника сохраняется отдельно.
Документный коммит сам по себе не меняет версию скриптов.

После проверки плана остановить службу этой доски и дождаться ручных
`setup.sh` / `test.sh`. Во время установки их не запускать. Команда проверяет
порт, launchd на Mac, процессы и блокировки, но не является диспетчером
всех возможных ручных запусков. Затем явно установить показанную версию:

```bash
/Users/helloworld10011/dev/oh-my-symphony/.venv/bin/python /Users/helloworld10011/dev/oh-my-symphony/ours/bin/project-update eve --apply --expect <полная-версия-из-просмотра>
```

Команда сохраняет резервную копию **до** замены файлов. Повтор установки
той же версии ничего не меняет. При замене файлов служба должна оставаться
остановленной: весь набор файлов не переключается одной операцией файловой
системы. Ошибка записи запускает возврат; аварийное завершение оставляет
журнал, который блокирует новую установку до восстановления.

Установка скриптов не означает готовность проекта. Для будущего запуска
нужно отдельно выполнить согласованный `project-doctor`, обновить замер
базы и проверить настройки. Установщик сам тесты и службы не запускает.

## Возврат

Идентификатор резервной копии показывается после установки и при следующем
просмотре. Сначала можно посмотреть обратный дифф, затем выполнить возврат:

```bash
/Users/helloworld10011/dev/oh-my-symphony/.venv/bin/python /Users/helloworld10011/dev/oh-my-symphony/ours/bin/project-update eve --rollback <ID> --dry-run --diff
/Users/helloworld10011/dev/oh-my-symphony/.venv/bin/python /Users/helloworld10011/dev/oh-my-symphony/ours/bin/project-update eve --rollback <ID>
```

Возвращается только последняя установка или указанный незавершённый журнал.
Восстановление не требует исходного репозитория: содержимое, контрольные
суммы, Unix-права и прежняя запись версии сохранены в журнале. При ручных
изменениях файлов, повреждении копии или другом незавершённом обновлении
команда отказывает, не затирая эти изменения. Принудительной перезаписи нет.

Журналы и запись версии находятся в папке доски:
`.ours-state/script-updates/current.json`, `history/<ID>.json`, `pending.json`
при незавершённой операции. `update.lock` — постоянная блокировка установщика;
её файл не удаляется. Эти данные не заменяют резервную копию всей доски.

**Особенность первого перехода EVE.** Если после установки уже появился
постоянный машинный файл `.locks/test.lock`, возврат исходного скрипта E3c,
который создавал каталог с тем же именем, требует отдельной миграции.
Установщик откажет до замены скриптов и не удалит этот файл: его удаление
может нарушить блокировку другого участника. До появления файла замка
первый переход обратим обычной командой. Возврат между версиями с одинаковым
файловым протоколом этой особенности не имеет.

## Описание комплекта

`bundle.json` содержит `schema: 1`, имя комплекта, словарь `files` и
при необходимости `machine_test_lock: true`. Источник и назначение каждого
файла имеют одинаковый относительный путь. Допустимы только `setup.sh`,
`test.sh`, `bin/...`; конфигурация, секреты, карточки и `.ours-state` в
список не допускаются. Источники должны быть обычными файлами в Git.

Для файла задаются `mode` (`0644` или `0755`) и `adopt_sha256`: известные
хеши прежних внешних версий для первой установки. Отсутствующий файл или
точная копия новой версии также допустимы. После регистрации установщик
сверяет файлы с записью установленной версии: ручная правка, удаление или
смена прав вызывают отказ. Удаляется только ранее управляемый файл,
которого больше нет в новом комплекте; остальные файлы папки не затрагиваются.

`--root` выбирает папку досок, `--kit` — комплект для доски с другим именем,
`--source` — репозиторий проверенного источника. Эти параметры полезны для
изолированных проверок; они не разрешают устанавливать непроверенную ветку
в работающую среду.
