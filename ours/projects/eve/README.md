# Скрипты проверки доски EVE

Версионируемая копия трёх файлов внешней доски `~/symphony-projects/eve/`:
`test.sh`, `bin/junit-merge.py`, `bin/test-lock.py`. Исходные `test.sh` и
`junit-merge.py` подготовлены в E3c 29.10.2026; исправления от 31.10 описаны
в `docs/our/reports/REPORT-18.md`.

Это комплект для существующей локальной доски, а не универсальная заготовка
проекта. Пути к Python, Node 24.22.1, `summarize.py` и общей папке замка
соответствуют машине Сергея. Для работы также нужны уже существующие
`project.toml`, `bin/typecheck`, установка зависимостей и тестовый загрузчик
проекта EVE. Эти файлы не переносятся и не переопределяются комплектом.

## Блокировка

`test.sh` открывает постоянный файл `~/symphony-projects/.locks/test.lock`
как дескриптор 9. Помощник `test-lock.py` получает исключительный `flock`
на унаследованном дескрипторе; оболочка сохраняет его на время первого
прогона и повтора. Завершение помощника не снимает замок. Если оболочка
погибла, но дочерний процесс ещё держит дескриптор, другой прогон не начнётся.
После закрытия последнего дескриптора блокировку освобождает ОС.

PID и возраст файла не используются для снятия замка. Файл остаётся после
прогона; его нельзя удалять, переименовывать или заменять при возможных
участниках. Пустой оставшийся файл не означает зависшую блокировку.
Ожидание ограничено прежним бюджетом `tests_s` за вычетом резерва прогона;
превышение даёт `ENV: test lock busy`, код 75.

Основание поведения дескрипторов — [документация Apple `flock(2)`](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/flock.2.html).
Проверки на Mac охватывают конкуренцию процессов, выход помощника, убийство
родительской оболочки и освобождение после завершения дочернего процесса.
Участники должны сохранять унаследованный дескриптор; программа, специально
закрывающая его, не удерживает блокировку после гибели родителя.

## Применение к внешней доске

Слияние PR и `post-merge` **не копируют** этот комплект в доску EVE.
Доска относится к другому репозиторию; применение выполняется отдельно,
в рамках явно согласованного обновления. Пока оно не выполнено, на доске
остаются прежние скрипты с замечаниями из REPORT-18.

Перед заменой трёх файлов сохранить текущие версии и убедиться, что служба
EVE и ручные прогоны её старого `test.sh` остановлены. Проверить отсутствие
старого каталога `test.lock`: новая версия отказывает при его наличии и
ничего из него не удаляет. Если каталог остался, сначала проверить прежнего
владельца и его дочерние процессы; автоматического удаления по PID нет.
Старую и новую версии запускать параллельно нельзя. Все три файла заменять
как один комплект при остановленных запусках; права исходных файлов сохранить.
`project.toml`, промпты, замеры и рабочие копии проекта при копировании не менять.

Пробные задания EVE из плана 29.10 сняты Сергеем 31.10. Папка
`~/dev/eve-pipeline` теперь занята отдельной разработкой EVE в Codex.
Наличие этого комплекта не разрешает запускать старые карточки, переключать
ту папку или проводить в ней проверочный прогон. Для новой пробы потребуются
актуальная задача, выделенная копия и новый замер по согласованию с Сергеем.

## Проверка комплекта

Из рабочей копии Symphony:

```bash
python -m ruff check ours
python -m pytest ours/tests/test_eve_board_scripts.py -q
python -m pytest ours/tests -q
bash -n ours/projects/eve/test.sh
```

Регрессии запускают настоящие конкурирующие процессы и JUnit-инструменты
во временных папках. Для сквозного запуска оболочки Node, `npm test` и
проверка типов подменены; код EVE и работающие доски не используются.
Это проверка обёртки, не новый замер полного набора Vitest.
