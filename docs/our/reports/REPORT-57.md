## Что получил чат проекта

По одному согласованному запросу конвейер возвращает адрес работающей доски,
инструкцию и фактически применённые настройки. Для новой задачи достаточно
названия и описания. Номер, пара разработчиков, режим и область работы
появляются автоматически. Две карточки, созданные до и после смены пары,
сохраняют свои назначения. Подтверждение оплаты относится к отдельной
карточке. [Вводная для чата](../PROJECT-SETUP.md) ·
[Вход для оператора](../../../ours/README.md#подключение-по-запросу-чата).

От прежней разработки использованы внешнее размещение доски, `project.toml`,
`project-render`, проверка конфигурации, штатная служба Symphony и обзор
проектов. В исходном `project-new` был обязательный поиск Claude. В обычной
форме номер по умолчанию начинался с `TASK`. Новый способ подключения работает
с выбранной API-командой и префиксом проекта. Существующая очередь Claude
доступна на своих прежних досках. Исторический маршрут проверен по
словарю, конфигурациям OMS и EVE и результатам OMS-9/OMS-10.
[Реестр наследия](REPORT-56.md) ·
[Проверка прежнего поведения](REPORT-54.md#проверка-подключения-api-профиля-oms).

На SSD создали отдельный Git-проект `example` с веткой `main` и одним
файлом `README.md`. Оператор просмотрел запрос, выдал этому проекту
локальное разрешение, клиент отправил запрос службе. Поднялась пустая
доска. Повтор вернул тот же адрес. Реестр обзора нашёл тот же проект и адрес.

В Chromium открыли настройки и создали задачу через обычную форму.
Заполнили только название и описание. Получили `EXAMPLE-1` в `Todo`,
DeepSeek Flash 4.1/high, Luna/max, режим «Экономия» и доступ к `README.md`.
Просмотр назначения довёл карточку до ожидания подтверждения. Платную
кнопку не нажимали. Работали только временные службы проверки. После неё
служба подключения и тестовая доска остановлены. Штатная диагностика
показала «проект готов», ошибок 0, предупреждений 1. Полная команда
`symphony` отсутствует в пути оболочки на этой машине, в рабочем процессе
используется путь к исполняемому файлу из окружения.

В целевой выборке прошли 224 проверки. Также прошли четыре проверки
браузерного и Node-интерфейса, включая существующие проверки выбора моделей
и доставки результата. Ruff прошёл для оболочки, ядра и тестов. Среди
проверенных случаев есть одновременные подключения, повтор после сбоя,
чужой проект или процесс, подмена ответа службы, конфликт каталога,
отключённая доска с задачами, изменение прав и повтор создания той же

## Границы приёмки

- Подключение работает на доверенной машине, где доступны репозиторий и
  локальная служба. Адрес открывается на этой машине. Для работающей
  совместимой доски профиль сверяется целиком, запуск остановленной рабочей
  доски остаётся решением оператора.
- Для обычного проекта полную проверку результата организует оператор.
  Автоматический адаптер GitHub настроен для публичного форка OMS на
  `our-main`. Полное платное выполнение задачи стороннего проекта
  в этой итерации не проверяли. Зависимость от ручного подтверждения
  каждого запуска останется предметом отдельного блока.
- Пару можно изменить в настройках доски, исключение для одной задачи
  выбирается до её запуска. Изменение согласованного режима, полномочий
  или полной проверки через интерфейс в этот блок не вошло. Gemini
  остаётся отдельным планируемым профилем.
- Основные OMS и EVE не запускались и не перенастраивались. Рассматриваемый
  код к рабочей установке на дату отчёта не применён. Расход на модели
  за проверки конструктора составил $0.
