## Коротко

У `test.sh` теперь есть контракт: последней строкой он печатает `PIPELINE_TESTS passed=<n> skipped=<n> failed=<n>` (её делает новый `ours/hooks/summarize.py` из отчёта JUnit XML). Новая команда `ours/bin/project-doctor` проверяет готовность проекта, гоняет `setup.sh` и `test.sh` в пробной рабочей копии базовой ветки, записывает замер в `.ours-state/baseline.json` и по нему заполняет `[timeouts]`. `check.py` при коде 0 требует строку итогов и сравнивает её с замером: агент, который убрал тест из запуска через конфиг раннера (сам файл теста не тронут), теперь ловится — проверено сквозным прогоном на настоящей службе **[запуск]**. Таймаут тестов один — `[timeouts] tests_s`; лимиты ходов ядра — в новом разделе `[limits]`.

## Лимиты ядра: точный смысл [код]

Счётчики живут в памяти службы (`_IssueDebug`), перезапуск службы их обнуляет (кроме продолжения после сбоя с чекпойнта: `dispatch.py:1493`).

- **`max_turns` (30)** — ходов за один запуск воркера по карточке (`attempt.py:1159`). Исчерпан без перехода в конечное состояние — запуск останавливается, продолжение не планируется, карточка уходит в `budget_exhausted_state` = `needs_human` (`worker_exit.py:902`, `helpers.py:292`). Ядро не примет `max_turns` меньше числа активных состояний (`preflight.py:24`), у нас 4 — это проверяет и `project.toml`.
- **`max_total_turns` (60)** — ходов по карточке по всем запускам (`attempt.py:614`, `worker_exit.py:279`). Откат `check.py` начинает новый запуск, счёт продолжается. Исчерпан — `needs_human`.
- **`max_attempts` (3)** — возвратов назад по активным состояниям (Verify → In Progress и т.п.), включая принудительные, когда этап не выполнил контракт (`agent_phase.py:178`). Возврат номер 4 переводит карточку в первое конечное состояние со словом «block» — `Blocked` (`helpers.py:284`). Откаты `check.py` из `Human Review` сюда не входят (`Human Review` не активное состояние, `helpers.py:38`): их считает наш `[checks] max_check_failures`.

**Важные для дневного/ночного контроля, но не добавлены** (по заданию): `agent.max_total_tokens` и `max_total_tokens_by_state` — потолок токенов в одном состоянии, при превышении воркер отменяется с `token budget exceeded` (по умолчанию выключен; главный кандидат на ночной потолок трат); `agent.max_retries` (3) — автоповторы после аварийного выхода, затем `Blocked`; `agent.max_state_turns` (30) — ходов в одном состоянии без смены этапа; `claude.turn_timeout_ms` (у нас 1 час). Ядро показывает расход всех этих лимитов по карточке (`api_views.py:458`: `attempt_turns`, `total_turns`, `state_tokens`, `retries`, `rewinds`, `reopens`).

## Решения и расхождения

1. **`workspace.code_repo` (K10)** в `our-main` нет (`grep` по `src/` пусто) — в шаблон не добавлен.
2. **«вверх(1,5 × setup)»** понято как округление вверх до целой секунды (для тестов в задании явно «до минуты»).
3. Сообщения `check.py` о строке итогов и базе — по-русски (в задании текст «запусти project-doctor»); остальные сообщения `check.py` остались английскими.
4. Нет `baseline.json` в режиме `hook` — откат карточки, как и при любой ошибке конфигурации (закрыто по умолчанию). Значит, проект без `project-doctor` будет гонять карточки до `needs_human`; поэтому `project-new` в конце печатает команду `project-doctor`.
5. Замер привязан к ветке: если в `project.toml` сменили `base_branch`, `check.py` отказывает «перезапусти project-doctor». Смену тестов в самой базовой ветке он не видит — только подсказка в тексте отказа.
6. В `ours/tests` (наши тесты, не тесты проекта) поправлены помощник `Env` (замер базы и строка итогов по умолчанию) и вызовы со старым ключом `test_timeout_s`; тест «старый ключ важнее» заменён на «старый ключ — ошибка».
7. В `run.sh` исправлено условие ожидания: раньше цикл мог закончиться на втором `Human Review`, если в `check.log` уже была запись об откате; теперь ждёт записи `pass`.
8. **Шаг 5 задания выполнен не дословно** — см. описание PR и запись в `DECISIONS.md`.

## Риски

- Строку итогов печатает `test.sh`, а тесты — это код агента: тест может сам напечатать поддельную строку. Последняя строка — от `summarize.py`, если тот отработал; при сбое `summarize.py` пример `test.sh` выходит с ошибкой, так что поддельная строка не засчитается. Сам отчёт JUnit пишется вне рабочей папки.
- Пока служба проекта запущена, `symphony doctor` внутри `project-doctor` выдаст FAIL занятого порта — запускать при остановленной службе.
