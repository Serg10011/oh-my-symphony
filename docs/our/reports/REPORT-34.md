## Вывод для Сергея

Штатный хаб — общая стартовая страница проектов в браузере. У каждого
проекта плитка: имя, пути репозитория/workflow/карточек, состояние службы
и кнопка открытия. Есть форма добавления проекта и Refresh. Интерфейс
английский; по умолчанию страница обслуживается на 127.0.0.1:8787.
Задачи и подзадачи просматриваются на отдельной доске выбранного проекта.

Для временной страницы входа основа уже есть: модель реестра и HTTP-вывод
принимают наши отдельные внешние workflow, существующая OMS распознаётся.
Подключение через штатное project add для нашей схемы не подходит:
оно требует workflow внутри репозитория и выполняет подготовку проекта.
Открытие выключенного проекта запускает его службу через service start.
Русской сводки задач, иерархии и счётчиков «ждёт Сергея / нужна помощь»
на текущей странице нет.

**Рекомендация:** пока сохранить действующие службы и регистрацию.
Если выбираем общий обзор, отдельным небольшим блоком подготовить страницу
только наблюдения поверх наших project.toml и API: явно показывать выключенную
службу, открывать работающую доску, собирать требуемую русскую сводку.
Кнопки запуска и новая регистрация потребуют отдельного решения.
Это предложение, не поручение реализовать страницу и не изменение архитектуры.

| Узнаётся ли наша OMS? | Реальный `ProjectRegistry.status` с getter только в памяти распознал OMS как running, EVE как stopped. Метод прочитал существующее состояние и проверил точный workflow через health API; сохранения реестра и запуска службы не было. |
| Что делает GET списка? | Только запрашивает состояния и возвращает сведения о проектах. В HTTP-примере выключенная EVE осталась выключенной, вызовов start не было. |
| Что делает Open? | Для уже работающей OMS повторного start не было. Для подставной выключенной EVE `/open` вызвал ровно один start только её; другая подставная служба сохранилась. Это штатная семантика кнопки Start and open. |
| Какие данные есть в списке? | id, name, repo, workflow, board, host, port, running, url, diagnostics. Задачи, подзадачи и их счётчики в этом ответе отсутствуют; UI строит плитки проектов. |
| Полностью ли list без записи? | `ProjectRegistry.list/load` берёт файловую блокировку. На новом временном пути созданы родительская папка и `.registry.json.lock`; сам JSON реестра не создан. Реальный реестр читался напрямую, без вызова этого метода. |
