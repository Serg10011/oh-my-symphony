# REPORT-13 — ветки, лог и diff в веб-доске при внешнем репозитории кода (TASK-K10)

**Задача:** `docs/our/tasks/TASK-K10-web-code-repo.md`. Ветка `core/web-code-repo` от `our-main`.
**Пометки:** **[запуск]** — проверено запуском (тесты на временных репозиториях); **[код]** — по чтению кода.

## Что сделано

Новый необязательный ключ `workspace.code_repo` — абсолютный путь к git-репозиторию кода. Если ключа нет или он пустой, всё работает как раньше: веб-доска смотрит в папку `WORKFLOW.md`.

С ключом пять маршрутов **только чтения** смотрят в репозиторий кода: список веток (`/git/branches`), лог (`/git/log`), ветки задач (`/git/task-branches`), сравнение (`/git/compare`), diff (`/git/diff`, в том числе по коммиту). Карточки для списка веток задач по-прежнему берутся с доски **[запуск]**.

Маршруты, которые меняют репозиторий (merge, push, pull request, удаление ветки), ключ не читают и работают с папкой `WORKFLOW.md`. Если там нет git, они отказывают — так и задумано: сливает человек сам **[запуск]**. Маршрут `remote-status` не входит в пять названных в задаче, поэтому остался на папке `WORKFLOW.md` **[код]**.

## Как устроено

- `workflow/builder.py`: функция `_validated_code_repo` читает ключ строго. Принимается только строка с абсолютным путём; `~` и `$VAR` не раскрываются. Дальше `git rev-parse --show-toplevel` должен вернуть ровно этот путь, то есть это корень репозитория, а не подпапка и не обычная папка. Иначе — `ConfigValidationError`. Проверка идёт при каждой загрузке `WORKFLOW.md`: на старте и при перечитывании **[запуск]**.
- `workflow/config.py`: поле `ServiceConfig.code_repo` (по умолчанию `None`), добавлено в конец.
- `webapi/context.py`: `_Ctx.code_dir()` — `code_repo` или папка `WORKFLOW.md`.
- `webapi/git_routes.py`: в пяти обработчиках чтения `workflow_dir` заменён на `code_dir()` (переименование, новой логики нет).

## Как проверено

Новые тесты: `tests/test_webapi_code_repo.py`, 8 штук, на временных репозиториях **[запуск]**:

- с ключом видны ветки `main` и `symphony/SEED-1`, лог, ветки задач, compare, diff и патч коммита внешнего репозитория; без ключа доска без git, как раньше, пустая;
- ключ главнее git-репозитория самой доски; без ключа виден репозиторий доски (прежнее поведение);
- merge, push и удаление ветки с ключом отказывают (`no_target` / `merge_*`, `no_remote`, `not_a_git_repo`); `main` в репозитории кода не сдвинулся, ветка осталась, файл фичи не появился, пустой удалённый репозиторий пуст;
- движок слияния получает папку доски, а не репозиторий кода;
- отсутствие ключа и пустая строка дают `None`; относительный путь, обычная папка, подпапка репозитория, несуществующий путь, число и список — ошибка конфигурации.

Прогоны: до правок 3878 прошли / 136 пропущены / 2 упали; после — **3886 / 136 / 2** (+8 новых, новых падений нет). Те же два падения окружения, что в REPORT-09: `test_pm_planning.py::test_stop_kills_term_resistant_group_after_leader_exits` и `test_pm_ui_node.py::test_pm_ui_node_regressions`. `ruff check src tests` и `symphony-pyright` — без замечаний. Существующие тесты не менялись.
