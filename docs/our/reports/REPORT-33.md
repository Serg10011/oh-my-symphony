## Что сделано и зачем

Перед старой `.clean` добавлена самостоятельная команда
`ours/bin/workspace-report`: русский обзор или JSON, без удаления.
Она различает зарегистрированные Git-копии, самостоятельные репозитории,
неизвестные папки, ссылки и служебные каталоги. Читает только два уровня
выбранного корня; сопоставляет `project.name` и `project.repo` известных
досок с реальной общей Git-папкой. Только при совпадении читает состояние
карточки с точным именем рабочего места. Заголовок карточки ограничен 64 КиБ,
тело и сохранённая история не нужны для этого сопоставления.

Показываются ветка, HEAD, изменения и число игнорируемых записей.
Ссылки не обходятся, чужое состояние карточки не приписывается папке;
ошибки не скрываются. В JSON всегда `read_only=true`, `deletion_assessed=false`.
Код 0 — обход завершён без ошибок, 1 — ошибка/неполная проверка, 2 — параметры.
Даже Done и чистый Git не означают, что папку можно удалить.
Инструкция — [ours/README.md](../../../ours/README.md).

Ядро, зависимости, очередь команд, post-merge, настройка запуска и промпты
не менялись. Самой `.clean`, новых исполняемых карточек и агентов нет.
Новая команда не отправляет запросы моделям, не пишет в базы, не управляет
службами и не меняет модели, лимиты или оплату Anthropic.

## Существенная проверка режима чтения

Git запускается без необязательных блокировок/записи индекса, с отключённым
fsmonitor и пределом 10 с на запрос. Унаследованные `GIT_*` очищаются, затем
явно задаются ограничения чтения: чужие GIT_DIR/GIT_WORK_TREE не меняют цель,
Git-трассировка не создаёт файл, отложенная загрузка объектов запрещена.
Никаких fetch, prune, ремонта, удаления или модифицирующих команд нет.
При запуске entry point также отключено создание Python bytecode.

Дополнительный опыт показал: обычный git status запускает clean-фильтр
настроенного репозитория при перечитывании файла того же размера, даже
если содержимое не изменилось. Оба варианта подтверждены подставным
фильтром во временном репозитории. Ранний полный прогон остановлен
после **524 PASS**, код 2 (KeyboardInterrupt); это не полный успешный прогон.

Исправление: перед status проверяются только имена настроенных clean/process
фильтров. Если они есть, status не вызывается, `status_checked=false`,
счётчики изменений `null`, причина видна и весь обзор отмечается неполным.
Фильтры не отключаются в конфигурации и не запускаются. Даже неиспользуемая
настройка фильтра считается основанием пропустить status; это намеренно
консервативный результат, а не вывод о чистоте файлов.
