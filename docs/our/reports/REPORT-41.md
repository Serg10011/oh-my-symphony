## Что подготовлено

Общий budget с max_usd и input_tokens_total для всех участников сессии.
Новый api_budget.py ведёт консервативную верхнюю стоимость генерации:
предварительный резерв до отправки, освобождение по проверяемому расходу,
удержание при неизвестном исходе. Decimal и округление вверх до микродоллара
исключают потерю остатка из-за float. Справочник ставок фиксируется в
состоянии; версия или срок не совпали — запуск блокируется до актуализации.
Проверка перед каждой генерацией сохраняется в журнале preflights.

Один ограниченный HTTP-обмен выделен из прежнего транспорта без новых
зависимостей: фиксированные адреса/ключи, отсутствие повторов, редиректов
и proxy из среды, прежние пределы размера и ожидания. OpenAI подсчитывает
вход по полному подготовленному содержимому; DeepSeek предоставляет
машиночитаемую ёмкость модели. При неудаче подсчёта эвристика не применяется.
Прежняя генерация OpenAI теперь явно запрашивает Standard, результат
содержит фактически возвращённый service_tier. В защищённой сессии другая
модель или неподтверждённый тариф останавливают работу без освобождения
резерва. Никакого перехода на более дорогой состав нет.

Консольный run требует budget. Старые состояния и низкоуровневый Python
run() сохраняют совместимость; для платного потребителя обязательна
передача require_budget=True, как уже делает CLI. Пустой/неверный ключ
по-прежнему отклоняется до запроса. Init/show локальны, ключи в состояние
и ошибки не добавляются. Реального API-запуска не было.

## Основание подсчёта и ограничения

Проверены официальные страницы 03.11.2026:

- [OpenAI token counting](https://developers.openai.com/api/docs/guides/token-counting):
  полный вход включает роли, границы и функции; одной токенизации текста мало.
- [OpenAI Responses](https://developers.openai.com/api/reference/ruby/resources/beta/subresources/responses/methods/create):
  service_tier=default выбирает Standard, ответ отражает реально применённый режим.
- [Luna](https://developers.openai.com/api/docs/models/gpt-6-luna) и
  [Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol): тарифы,
  порог длинного контекста, региональные надбавки.
- [Prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching):
  cache reads и writes — части входа, отдельные сроки записи имеют разные ставки.
- [DeepSeek models](https://api-docs.deepseek.com/api/list-models/): context_window
  включает вход и выход, поэтому полное окно — консервативная граница входа.
- [DeepSeek prices](https://api-docs.deepseek.com/quick_start/pricing/): пиковые
  цены выше внепиковых; резерв берёт пиковую ставку.

Фиксированный справочник проверен 03.11, действует по 10.11.2026 UTC
включительно. Для OpenAI резерв покрывает максимальную ставку записи
12h, длинный контекст и 10% региональную надбавку. По известным cached/write
счётчикам верхняя оценка уменьшается без двойного подсчёта. Неизвестные
cache writes считаются по более высокой ставке. Для DeepSeek все входные
токены до ответа резервируются как целое окно, поэтому первый короткий
запрос тоже требует около $1,40 свободного резерва. Это ограничение
строгой консервативной оценки; реальный счёт может оказаться существенно ниже.

Граница относится к генерации по сохранённым ставкам и контрактам
подсчёта/выхода провайдера. Это не фактический счёт и не лимит всего аккаунта:
cost_usd остаётся null, upper bound показан отдельно. Служебные запросы
подсчёта/метаданных записаны отдельно; реальная тарификация, баланс,
списание бонуса и соблюдение контрактов провайдерами ещё не проверены.
Скрытое изменение цен внутри срока справочника локальная программа
автоматически обнаружить не может. Другой тариф/модель, превышение входа
или выхода и некорректный расход блокируют продолжение; известное
превышение сохраняется в истории, не маскируется установленным бюджетом.

Это отдельный текстовый контур, без файлов/команд и регистрации на досках.
Экономия не измерена, действующие Anthropic и службы не меняются.
