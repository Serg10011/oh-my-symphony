**Как работает.** Проверки по порядку: конфиг (`$SYMPHONY_WORKFLOW_DIR/gate.toml` или `--config`; путь внутри рабочей папки — отказ; неизвестный ключ — отказ, чтобы опечатка не отключила проверку) → база (`git merge-base HEAD <base_ref>`) → запрещённые пути → существующие тесты → форма карточки → тесты проекта. Нарушения быстрых проверок собираются все сразу; тесты проекта запускаются, только если быстрые прошли. Любой непредусмотренный сбой — отказ (в `gate` код 1, в `hook` — откат).

- **Изменённые пути** — объединение четырёх списков: коммиты от базы, индекс, рабочее дерево, неотслеживаемые (`--no-renames`, поэтому у переименования учитываются оба имени). Плюс файлы с флагами `skip-worktree`/`assume-unchanged` (кроме доски): их правки `git diff` не видит, поэтому содержимое сверяется с индексом. Настройки репозитория, которые могли бы «спрятать» изменения (`core.fsmonitor`), отключаются на время вызовов git.
- **Тесты не изменены** — для каждого файла базы, совпавшего с `test_globs`: режим и хеш в HEAD и в индексе равны базе, а хеш сырых байтов на диске (`git hash-object --no-filters`) равен хешу из базы. Это побайтное сравнение, оно ловит и правку, спрятанную через `skip-worktree`.
- **Тесты проекта** — `bash -lc`, своя сессия (`start_new_session`), вывод в файл, а не в канал (фоновый процесс, держащий канал, не превратит успех в таймаут). Группа процессов убивается всегда: при таймауте и после обычного завершения (остатки).
- **Хук** читает `state` из файла карточки; не `Done`/`Human Review` — выход без действий. При провале: счётчик +1 → `board mv` в `In Progress` (или `needs_human` на `max_check_failures`) → перечитывание карточки (не сменилось — ошибка в журнал) → заметка `## Check Failure` → журнал. Хвост вывода в заметке — блок с отступом 4 пробела: строка `## ...` из вывода тестов не станет разделом карточки (иначе агент мог бы «напечатать» себе `## Wiki Updates`).

**Решения там, где задание оставляло выбор.** (1) Заметка пишется штатным API трекера `FileBoardTracker.append_note` через `$SYMPHONY_PYTHON -P -c` (`-P` — текущая папка агента не попадает в пути импорта); запасной путь — атомарная замена файла под тем же файлом блокировки `kanban/.locks/<ID>.lock`. В журнал пишется, каким путём (`note: tracker|file`). (2) Глобы — своя реализация: от корня репозитория, без учёта регистра (на Mac файловая система регистр не различает), `*` внутри одного сегмента, `**` — любое число сегментов; 31 тест. (3) `forbidden_paths` дополняет встроенный список, `test_globs` и `required_sections` заменяют. (4) В `gate` форма карточки проверяется всегда (шлюз вызывается только при приёмке Done). (5) `ours/tests` гоняется отдельной командой `python -m pytest ours/tests -q`, а не через `testpaths`: так цифры основного набора не меняются; `ruff` — `python -m ruff check ours`.

## Ответы на вопросы

**Q1. Как дописать раздел и сменить состояние.** Команды «дописать раздел» в `symphony board` нет (`cli/board.py:400-512`: init, ls, new, mv, update, show, graph) [код]. Штатный путь — метод трекера `FileBoardTracker.append_note` (`trackers/file.py:983`), им пишут заметки сам оркестратор и веб-API. Состояние — `symphony board mv` → `FileBoardTracker.transition` (`file.py:947`); имя статуса не проверяется. Обе записи идут под блокировкой файла карточки и со сверкой `updated_at` (`file.py:896-945`) [код]. **Гонки с агентом этой карточки нет:** `after_run` вызывается после конца хода (`attempt.py:898`). Другие писатели (веб-доска, агенты других карточек через общую `kanban`) упорядочиваются той же блокировкой. Настоящая гонка — со сверкой ядра, см. «Риски», п. 1.

**Q2. Переменные `after_run`.** Есть: `SYMPHONY_WORKFLOW_DIR`, `SYMPHONY_PYTHON`, `SYMPHONY_WORKSPACE_ROOT` (`workspace.py:877-895`), значения доски и веток (`SYMPHONY_BOARD_ROOT`, `SYMPHONY_BOARD_ROOT_NAME`, `SYMPHONY_FEATURE_BASE_BRANCH`, `SYMPHONY_MERGE_TARGET_BRANCH`), `SYMPHONY_CLI` из окружения оркестратора (`core.py:604`). **`SYMPHONY_ISSUE_ID` в `after_run` нет** — только в `after_done` (`workspace.py:714`) и в шлюзе (REPORT-04) [код]. Имя папки — `workspace_key(ID)`: символы вне `[A-Za-z0-9._-]` заменяются на `_` (`issue.py:89-95`). Для ID, проходящих нашу проверку, имя папки совпадает с ID; остальные скрипт и так отвергает [код; путь «ID из имени папки» через настоящий `_run_hook` — запуск].

**Q3. Дети хука при таймауте** [запуск, настоящий `WorkspaceManager._run_hook`, `timeout_ms` = 2000]. Ядро убивает только `bash` (`subprocess.run` → `kill()`), дети живут дальше: обычный `sleep` из хука пережил таймаут. Три варианта:
- `check.py` — первая строка, дальше есть другие строки: `check.py` остаётся сиротой, за ≤0,2 с замечает смену родителя, убивает группу тестов, пишет `skipped`, карточку не трогает (поздний откат после того, как ядро пошло дальше, вреднее, чем никакого).
- `check.py` — единственная команда: `bash` подменяет себя им (exec), SIGKILL достаётся самому `check.py`, а тесты в своей сессии живут до естественного конца. Отсюда в README требование `… check.py hook || true`; с ним поведение как в первом варианте [запуск].
- В обоих случаях карточка остаётся в Done, решает шлюз.

## Риски и что не сделано

1. **Сверка ядра вмешивается в долгий хук** [код]. Если карточка лежит в Done/Human Review дольше 60 с, а агент 60 с не показывал прогресса, сверка отменяет воркера даже посреди `after_run` (`retry_reconcile.py:906-924`; `exit_started_at` ставится только после выхода из цикла ходов, `attempt.py:248`). Отмена не останавливает хук (поток и подпроцесс), дальше для Done — снимок и шлюз параллельно с тестами хука, для Human Review — удаление рабочей папки (`retry_reconcile.py:1017-1040`). Скрипт это распознаёт: папка исчезла во время проверки → `skipped`, без отката и без счётчика (иначе ложный провал). Итог: для наборов тестов дольше ~45 с вердикт фактически даёт шлюз. Проверить на Mac; если подтвердится — отдельная быстрая команда для хука (одна строка в конфиге) или правка ядра.
2. Хук, убитый по `hooks.timeout_ms`, Done не останавливает — шлюз обязателен. Если `check.py gate` убит по `done_gate_timeout_ms`, его тесты (в своей сессии) доживают сами — поэтому `test_timeout_s` меньше обоих таймаутов.
3. Не закрыто: неотслеживаемые файлы, скрытые `.gitignore`/`info/exclude`, в ветку не попадут, но влияют на прогон тестов (например, игнорируемый `conftest.py`); настройки git в worktree принадлежат агенту; агент работает под тем же пользователем и физически может править файлы вне своей папки — защищают только правила.
4. Состояние карточки читается своим разбором шапки (строка `state:`), а не YAML ядра; экзотический YAML может прочитаться иначе. Нет карточки — в хуке ошибка в журнал, отката нет.
5. Глобы от корня: `.env` ловится только в корне; `**/.env` при нужде добавить в конфиг.
6. Контракт Document ядра принимает `## Human Review` вместо `## As-Is -> To-Be Report` (`contracts.py:156-157`); наше умолчание (по заданию) требует оба раздела `## Wiki Updates` и `## As-Is -> To-Be Report`.
