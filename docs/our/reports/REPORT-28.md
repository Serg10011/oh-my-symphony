## Результат

Новый `ours/bin/check-report BOARD_PATH` печатает JSON с единственным ключом
`failures`. Библиотека `ours/hooks/check_report.py` последовательно читает
только `.ours-state/check.log`; последняя значимая запись hook/gate по ID
определяет текущий отказ. `pass` удаляет прежний отказ, fail/error/rollback:*
сохраняются, остальные режимы и исходы не меняют результат. Сортировка —
лексикографическая по ID, время события не используется как порядок.
Дополнительные поля не публикуются, строки и русский текст сохраняются.

Отсутствующий лог в существующей доске даёт пустой список. Неверные аргументы
возвращают 2; отсутствие доски, ошибка чтения, повреждённые UTF-8/JSON и
нарушение схемы hook/gate возвращают 1. Ошибки строк содержат номер, но не
содержимое записи. Вывод JSON начинается только после полного успешного
чтения, поэтому повреждение поздней строки не выдаёт частичный результат.

Код не вызывает subprocess, Git, сеть, агента или команды конвейера.
Настройки, карточки, история и рабочие службы не менялись. Новых зависимостей
нет; существующие тесты, `src/` и `tests/` не правились. README описывает
команду. Это диагностическое чтение, без manager-diagnose и лестницы моделей.
