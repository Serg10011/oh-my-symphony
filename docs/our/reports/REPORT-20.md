## Результат

В S4-27 доставка останавливалась при сдвиге базы или сокращённой проверке
`skipped-docs`. S4-28 добавляет полный повтор без агента: при сдвиге базы
создаётся кандидат M с двумя родителями (источник, база); при прежней базе
и `skipped-docs` проверяется исходный коммит. Локальные ветки карточки
и её рабочая папка сохраняются.

Во временной detached-копии выполняются быстрые проверки относительно
текущей базы, setup.sh и test.sh. Запуск выделен из project-doctor в
`ours/hooks/project_trial.py`: прежнее очищенное окружение, короткий PATH,
3600 с на скрипт, отдельная группа процессов и завершение группы в конце.
Быстрые проверки повторяются после скриптов; изменение проверяемого дерева
останавливает доставку. Конфликт, плохие итоги и таймаут переводят карточку
в needs_human с причиной; значения ключей скрываются. Конкурентная правка
карточки человеком сохраняется.

Итоги сравниваются с историей S4-25 для текущего конца базы по правилу E2.
Успешный замер кандидата записывается в baselines.json с его SHA и точкой
сравнения; baseline.json и таймауты доски не заменяются. Общий baselines.lock
защищает писателей doctor/deliver от потери параллельной записи. Хранятся
до 50 замеров базы и отдельно до 50 кандидатов: повторные доставки не
вытесняют историю базы.

Перед отправкой повторно сверяются источник, база в клоне и GitHub,
карточка, настройки и доказательства проверки. Пуш остаётся только в
deliver/<ID>, без force. При сбое PR повтор использует уже опубликованный
проверенный коммит. Сдвиг базы после публикации не вызывает переписывания
ветки: доставка останавливается для разбора.

Для Done дополнены записи «влито»: исходный коммит/дерево связываются с D
и его деревом. Шлюз проверяет Git-объекты и включение исходного коммита в D;
неизменённая исходная папка либо точное дерево D принимаются без лишнего
прогона. Подмена доказательства или другая правка такой пропуск не дают.

## Найденный задел прежней разработки

- S4-27 уже содержит проверку дерева, возобновление после сбоя PR и запрет
  force; приложение TASK-S4-27 подробно задаёт часть Б. Эти решения сохранены.
- Старое подтверждение Done ожидало одинаковое дерево карточки и доставки.
  После включения новой базы это разные деревья, поэтому понадобилась
  проверяемая связь исходного коммита с D, а не ослабление сравнения.
- История S4-25 хранила последние 50 записей без различия. Добавление
  промежуточных кандидатов потребовало отдельных пределов, чтобы не терять
  реальные замеры базы; прежние правила для истории без кандидатов сохранены.
- Очередь уже следит за своим кодом после выполненной через неё .merge.
  При обновлении вне очереди этот путь не вызывается: новый бюджет требует
  контролируемого перезапуска inbox-runner после завершения активной команды.

## Применение и ограничения

После приёмки: слияние PR в our-main, штатный post-merge, проверка отсутствия
активной команды очереди и её контролируемый перезапуск для бюджета 9000 с.
Запуск пробной карточки — отдельное решение Сергея. В разработке ни службы,
ни оплата, ни рабочие копии соседнего чата не менялись.

Последняя сверка базы и пуш не являются одной атомарной операцией сервера:
база может измениться сразу после сверки. Проверенные D и база явно
показываются в PR; слияние принимает Сергей. При неизвестном замере
сохраняется прежнее правило S4-25: полный прогон без провалов, без сравнения
с отсутствующим количеством тестов. Уборка finally покрывает нормальные
ошибки; SIGKILL/отключение питания могут оставить временную папку.
