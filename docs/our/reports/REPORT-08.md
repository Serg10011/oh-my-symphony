# REPORT-08 — стоимость запуска `runs.cost_usd`

Задача: `docs/our/tasks/TASK-K07-cost-usd.md`. Ветка `core/cost-usd`. Пометки: **[запуск]** — проверено запуском (тесты, команды), **[код]** — по чтению кода.

## Что сделано

Каждый запуск теперь знает свою стоимость: колонка `runs.cost_usd`, поле `cost_usd` в `GET /api/v1/runs` и `GET /api/v1/runs/{id}`, поля в событиях `turn_completed` и `run_completed` [запуск].

Как считается (`orchestrator/agent_phase.py:1252`, `_apply_cost_usd`): `total_cost_usd` из кадра `result` — это стоимость **всей сессии claude на данный момент**, поэтому стоимость хода = текущее значение − прошлое значение той же сессии. Сессию узнаём по `entry.resume_session_id` (его ставит событие `session_started`). Если сессия другая или значение меньше прошлого (сброс), берётся всё значение. Пустое поле, строка, `null`, `bool`, NaN, бесконечность, отрицательное число — пропускаются, стоимость не меняется; если за весь запуск не пришло ни одного годного значения, в колонке `NULL`, не 0 [запуск].

Событие `turn_completed` несёт три числа: `turn_cost_usd` (ход), `cost_usd` (запуск на сейчас), `session_cost_usd` (сырое накопительное значение сессии — нужно для продолжения после рестарта). Колонка `runs.cost_usd` обновляется после каждого хода (как токены), поэтому при падении службы в строке остаётся стоимость на последний записанный ход. `run_completed` несёт итог. Старые базы не трогаются, миграций нет: у прежних запусков `NULL`; у codex тоже `NULL` (он стоимость не присылает) [запуск].

Ход, закончившийся ошибкой (`result` с `is_error`), тоже считается: деньги потрачены [код + тест на сброс/цепочку].

## Ответ на п. 3: продолжение сессии после рестарта

Где хранится `session_id` [код]: `RunRegistry.checkpoint_completed_turn` после каждого завершённого хода пишет `resume_session_id` в строку запуска (`run_registry.py`); при рестарте `acquire_continuation_run` создаёт **новую** строку запуска с `continued_from_run_id`, а `attempt.py:541` возобновляет ту же сессию claude (`--resume`). Своей колонки для накопительного значения нет, а миграции запрещены.

Решение — без миграции: значение берётся из последнего события `turn_completed` предыдущего запуска (`session_cost_usd`), `run_registry.py:366`, и передаётся в `ContinuationCheckpoint.session_cost_usd`; `attempt.py:558-559` ставит его базой. Первый ход после возобновления считается от неё: в тесте 0.0595641 − 0.0573399 = 0.0022242 [запуск]. Каждая строка запуска хранит только свои траты; стоимость карточки = сумма по цепочке `continued_from_run_id`.

Когда база не найдётся (события предшественника вычищены лимитом хранения или не записались из-за блокировки базы — запись событий «лучшая попытка», `append_attempt_event`), первый ход после возобновления **завышен на всё, что сессия потратила до рестарта**; в журнал идёт `cost_baseline_missing` (warning). Оба исхода закреплены тестом `test_resumed_session_after_restart_counts_from_persisted_value[True/False]` [запуск]. Если между последним записанным событием и рестартом было ещё что-то потрачено (ход с ошибкой, прерванный ход), оно попадёт в первый ход продолжения — не потеряется и не задвоится, кроме редкого случая «ход с ошибкой + плавная остановка службы», где этот ход учтётся дважды [код].

## Отличия от описания задачи

- **Журнал при смене сессии:** при смене `session_id` пишется `cost_session_changed` уровня **info**, не warning. Причина: каждый переход этапа (In Progress → Verify → …) нормально открывает новую сессию claude, и warning был бы в каждом запуске. Warning остаётся для сброса (`cost_session_reset`) и для продолжения без базы (`cost_baseline_missing`). Если нужен warning и при смене — одна строка.
- Тест (д) идёт настоящим `GET /api/v1/runs` через aiohttp и настоящий `Orchestrator` + `RunRegistry` на SQLite, кадры подаются в настоящий `ClaudeCodeBackend` [запуск].
- Номера строк в REPORT-06 немного сдвинуты (`complete_run` на 529, а не 538); на маршрут не влияет.
