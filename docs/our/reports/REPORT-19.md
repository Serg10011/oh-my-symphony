## Результат

Исправления E3c уже хранятся в Git, но внешняя доска EVE содержит прежние
копии. Добавлена команда `ours/bin/project-update`: по умолчанию показывает
версии и план, с `--diff` — содержимое изменений; `--apply --expect <версия>`
устанавливает просмотренный комплект, `--rollback <ID>` возвращает прежний.
Общие настройки по-прежнему собирает `project-render`.

Источник — зафиксированные Git-объекты `HEAD`, состав задаёт
`ours/projects/eve/bundle.json`. Незакоммиченные файлы не используются.
Версия зависит от описания комплекта, содержимого и прав, а не от последнего
документного коммита. Происхождение записывается отдельным Git SHA.
Сейчас комплект содержит только `test.sh`, `bin/junit-merge.py` и
`bin/test-lock.py`. Для новых проектов нужен собственный комплект.

До записи сохраняются содержимое и Unix-права прежних файлов, новая версия
и прежняя запись установки. Журнал в `.ours-state/script-updates/` позволяет
восстановиться без исходного репозитория. Прерывание блокирует новую
установку до восстановления. Неизвестные локальные изменения и
повреждённые резервные копии вызывают отказ; принудительной перезаписи нет.
Установщик проверяет порт, launchd, процессы и блокировки. Службы, тесты,
агенты и карточки не запускаются; код приложения, настройки, замеры и
неперечисленные файлы не меняются.

## Просмотр настоящей доски

После фиксации исходников в Git выполняется только просмотр EVE с
проверкой контрольных сумм её файлов до и после. Результат будет добавлен
до предъявления PR на приёмку. Реальная установка в эту проверку не входит.

## Ограничения

- Доска должна быть остановлена; ручные прогоны нельзя запускать одновременно
  с установкой. Проверки обнаруживают текущую активность, но не блокируют
  все возможные способы запуска процессов. Весь набор файлов не меняется
  одной атомарной операцией файловой системы.
- Журнал проверен для ошибок записи и гибели процесса. Устойчивость при
  отключении питания этим прогоном не подтверждалась. Он также не заменяет
  резервную копию всей папки доски.
- Первый возврат EVE на старый скрипт, создающий каталог `test.lock`, возможен
  обычной командой только до появления постоянного файла с тем же именем.
  После первого запуска нового тестового скрипта нужна отдельная миграция:
  установщик отказывает до возврата и не удаляет постоянную блокировку,
  которую может использовать другой участник. Возврат между новыми версиями
  с файловой блокировкой этого ограничения не имеет.
- После установки готовность EVE и новый замер базы проверяются отдельно
  перед согласованной пробой. Старые задания сняты; занятый соседним чатом
  `eve-pipeline` не используется для проверки или запуска конвейера.
