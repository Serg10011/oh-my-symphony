# REPORT-66 — переключение OMS и EVE

## Результат разработки 14.11.2026

База `17f0ebd`, ветка `codex/safe-board-switch`. Сергей разрешил
разработку показанного блока. Выпуск подготовлен локально, публикация,
приёмка и установка ещё не проведены.

Старый переключатель вызывал `POST /open`, который запускал службу
целевого проекта. На EVE колонка Todo входит в активные состояния Claude,
поэтому запуск службы и просмотр доски имели разные последствия для задач.
Штатный переключатель, существующие колонки, формат Markdown и выбор
по файлам карточек сохранены. Управляемые внешние доски берутся из
`~/symphony-projects`. Источник уже используется в нашем обзоре проектов.
Отдельная запись в реестре для них не требуется.
[Исследование хаба](REPORT-34.md) · [Исторический профиль EVE](REPORT-18.md).

При выборе выключенной доски список и текст карточек читаются с диска.
Сохранённое представление открывается в той же вкладке. Для файловой
карточки с ручным стартом есть кнопка «Запустить задачу». Одно действие
проверяет версию карточки, при необходимости поднимает службу с ручным
режимом и ставит в очередь выбранную карточку. Если служба уже работает,
она должна подтвердить, что загрузила ручной режим. Старый workflow без ручного
режима разрешает просмотр. Файловый трекер и диспетчер проверяют границы
в ядре, чтобы обычный опрос и повтор подчинялись тому же условию.
Подзадачи получают допуск при их штатном выпуске из сохранённого плана.
API-команда использует свою очередь подтверждений. Составной маршрут
API не входит в блок. [Прежний маршрут](REPORT-54.md#наследование-маршрута-oms-и-выбор-моделей).

## Проверки и применение

В Chromium сверены переход с копии OMS на остановленную копию EVE,
чтение карточки, возврат и один запуск по кнопке. На OMS скопированы
19 карточек. Канбан EVE сейчас пуст, поэтому на её копии использованы
две проверочные карточки Todo. Переключение отправило только запросы чтения.
Сразу после подготовки службы диспетчер получил только EVE-1,
байты EVE-2 совпали. Для проверки использован встроенный симулятор агента.
Байты исходных карточек OMS и EVE сверены до и после. Расход API — $0.

Ядро: 846 целевых тестов в ходе разработки. После укрепления проверки
работающей службы повторно прошли 576 тестов HTTP, запуска служб,
диспетчера и API-команд. Генерация профилей, подключение проектов,
восстановление и подготовка подзадач: 105 тестов. Ruff, синтаксис
JavaScript и `git diff --check` прошли.

Общий прогон `9027519` на Mac дал 6757 прошедших тестов, 159 пропусков
и три отказа. Все отказы были в тестах, которые ставили карточку в Plan
или In Progress и ожидали исполнения без допуска. Тесты получили явный
допуск там, где проверяют зависимости или активное состояние. После
исправления 41 проверка планирования и подзадач прошла. Между общим
прогоном и адресной проверкой изменились только два файла тестов и
запись результата. Это общий прогон и адресная перепроверка, их числа
сохранены раздельно.

Установка OMS использует её существующий цикл `post-merge`. У EVE
свой репозиторий и старый сохранённый workflow. При сверке генератор
предложил ещё колонку Merging и сохранение её рабочей копии. Для этого
блока в существующей EVE следует применить только ручной старт, сохранив
фактические колонки, пути и параметры модели. Это отдельная операция
в согласованной установке. Рабочие службы и профили не менялись.
