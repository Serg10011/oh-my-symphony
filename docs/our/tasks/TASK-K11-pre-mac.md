## 2. Пробный прогон project-doctor в урезанном окружении
Сейчас setup.sh и test.sh в пробе получают всё окружение терминала. При автозапуске службы
(launchd) PATH будет минимальным, и скрипт, работающий в терминале, там упадёт. Запускай пробу
с окружением только из: PATH=/usr/bin:/bin:/usr/sbin:/sbin, HOME, USER, LOGNAME, LANG и LC_ALL
(если заданы), TMPDIR, плюс SYMPHONY_PYTHON и SYMPHONY_WORKFLOW_DIR. При FAIL setup.sh или
test.sh добавь в вывод подсказку: «скрипты должны сами задавать инструменты полными путями
(node, npm, python …), а не полагаться на PATH терминала».
Тесты: скрипт, вызывающий программу вне урезанного PATH без полного пути, падает с подсказкой;
тот же скрипт с полным путём проходит.
Заготовки setup.sh и test.sh в project-new: в комментариях явное правило полных путей и пример
`export PATH="/полный/путь/к/node/bin:$PATH"` с проверкой версии в первой строке.
Попутно: в run_script определяй признак таймаута ДО killpg (сейчас после, из-за чего вместо
«не уложился» может быть «код -9»); тест.
