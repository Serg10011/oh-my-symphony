## Что установлено запуском на Mac (трёхходовая проба с --resume, один session_id на все ходы)
Кадр `result` отдаёт `total_cost_usd` НАКОПИТЕЛЬНО за всю сессию claude, а блок `usage` за ход:
- ход 1: total_cost_usd = 0.0329794; usage: input 2, output 3, cache_creation 7953, cache_read 11334
- ход 2: total_cost_usd = 0.0573399; usage: input 2, output 3, cache_creation 5742, cache_read 13585
- ход 3: total_cost_usd = 0.0595641; usage: input 2, output 3, cache_creation 65, cache_read 19302
- `modelUsage.<модель>.cacheReadInputTokens` и др. тоже накопительные: 11334 → 24919 → 44221;
  `modelUsage.<модель>.costUSD` совпадает с `total_cost_usd`.
Стоимость хода = текущее значение минус предыдущее значение ТОЙ ЖЕ сессии: 0.0330, 0.0244, 0.0022.
`costBasis: "list"`: цена по прейскуранту (на подписке условная).
Эти числа используй как фикстуру тестов.

## Цель
Записывать в `runs.cost_usd` реальную стоимость запуска (сумма приращений), отдавать её в
`GET /api/v1/runs` (поле `cost_usd`) и нести в событиях `turn_completed` / `run_completed`.

## Требования к семантике
1. Приращение хода = value − last для той же session_id. Новая session_id, либо value < last
   при той же session_id (сброс), = сессия началась заново: приращение = value целиком,
   плюс предупреждение в журнал.
2. Нет `total_cost_usd` в кадре, нечисло, bool, NaN, inf или отрицательное = стоимость не
   меняется; если за весь запуск не пришло ни одного корректного значения, `cost_usd` остаётся
   NULL (не 0).
3. Продолжение сессии после рестарта службы или нового запуска карточки (crash_continuation,
   resume): найди по коду, где сохраняется session_id для возобновления, и выясни, можно ли
   сохранить рядом последнее накопительное значение. Если можно дёшево, сохраняй, чтобы
   приращение первого хода после возобновления считалось от него. Если нет, опиши в отчёте, как
   именно считается этот случай (ожидаемо: завышение на накопленное до рестарта) и сколько строк
   стоит исправление. Не молчи об этом.
4. Тип `usage: dict[str, int]` (backends/per_turn.py и др.) не должен пострадать: если расширение
   типа тянет за собой правки в других местах, держи стоимость отдельным полем, а не в `usage`.
5. Старые базы не трогай: у прежних запусков в колонке NULL. Миграций не добавлять. Колонка
   `runs.cost_usd` есть (migrations.py:152, REPORT-06).
