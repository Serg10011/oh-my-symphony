# S4-38 — сводка последних отказов check.py

Нужна небольшая утилита диагностики из старого пункта ROADMAP. Это первый
самостоятельный кусок отчёта по провальным задачам; роль manager-diagnose,
лестница моделей, агенты и работающие доски в задачу не входят.

Результат: `ours/bin/check-report BOARD_PATH` читает только
`BOARD_PATH/.ours-state/check.log` и печатает JSON с единственным ключом `failures`.
Способ реализации выбирает разработчик.

## Критерии (5)

1. Для каждого `id` используется последняя по порядку строк значимая запись
   режима `hook` или `gate`: `pass`, `fail`, `error`, `rollback:*`.
   `pass` убирает прежний отказ; остальные из этого списка показываются.
   Другие режимы и исходы (например, `skipped`, `baseline_unknown`) игнорируются.
2. `failures` — список без повторов, лексикографически отсортированный по id.
   Элемент содержит исходные строки `id`, `at`, `mode`, `outcome`, `reason`.
   Дополнительные поля лога не выводятся. Форматирование JSON свободное,
   русский текст сохраняется. Пустые строки игнорируются; отсутствующий лог
   в существующей папке и пустая история дают `{"failures": []}` и код 0.
3. Отсутствующая папка, ошибка чтения, неверный UTF-8/JSON, JSON не объект
   или отсутствие/нестроковый тип любого из пяти полей у записи hook/gate —
   код 1 и понятная ошибка stderr без traceback и без содержимого строки.
   Для повреждённой строки указывается её номер. Ошибка аргументов — код 2.
4. Чтение не меняет файлы доски и не запускает команды конвейера, Git,
   сеть или агентов. Новых зависимостей и изменений src/, tests/, существующих
   проверок нет. Код ограничен новым CLI/модулем в ours и новыми тестами;
   README получает краткое описание команды.
5. Проверки нового CLI, Ruff ours и полный ours/tests пройдены. Обычные
   TASK-S4-38, REPORT-28, текущие DECISIONS и ROADMAP отражают результат,
   команды и ограничения. Слияние и применение не разрешены.
