## Цель
Один скрипт `ours/hooks/check.py` (только стандартная библиотека, Python >= 3.11, читает TOML
через tomllib) с двумя режимами, пример конфига и тесты.
- `check.py gate` — запускается как `agent.done_gate_command`. Код 0 = пропуск. Любой другой исход
  = отказ. Печатает причину и хвост вывода тестов (до ~4 КБ) в stdout.
- `check.py hook` — запускается ПЕРВОЙ строкой `after_run`. Читает состояние карточки. Если оно не
  `Done` и не `Human Review` — ничего не делает (код 0, тесты не запускает). Иначе выполняет все
  проверки; при провале возвращает карточку и дописывает в неё раздел `## Check Failure`
  (причина и хвост вывода). Код возврата хука всегда 0 (ядро ошибки after_run проглатывает).

## Проверки (общие для обоих режимов; быстрые идут первыми, тесты проекта последними и только
## если быстрые прошли; в причину собирай все найденные нарушения быстрых проверок)
1. Конфиг: `$SYMPHONY_WORKFLOW_DIR/gate.toml` (или `--config <путь>`). Нет файла, ошибка разбора,
   нет обязательного ключа (`base_ref`, `test_command`) = отказ. Конфиг НИКОГДА не читается из
   рабочей папки агента или ветки.
2. База: `git merge-base HEAD <base_ref>` в рабочей папке. Не git, нет HEAD, ref не найден,
   merge-base не определился = отказ.
3. Запрещённые пути. Любой файл, изменённый относительно базы (закоммиченный, в индексе, изменённый
   в рабочем дереве, неотслеживаемый, удалённый, переименованный: учитывай оба имени), совпавший
   с глобами `forbidden_paths` = отказ. Умолчания в коде (конфиг дополняет): `WORKFLOW.md`,
   `gate.toml`, `ours/**`, `.github/**`, `.git/**`, `.env`, `.env.*`, `**/*.pem`, `**/*.key`.
   НЕ включай `.symphony/**` и `kanban/**`: агент легально пишет туда.
4. Существующие тесты не изменены. `test_globs` (умолчание: `tests/**`, `**/test_*.py`,
   `**/*_test.py`, `**/*.test.ts`, `**/*.test.tsx`, `**/*_test.go`, `**/*.spec.*`). Файл,
   совпавший с глобом и существовавший в базе, должен быть побайтно равен базе в HEAD и в рабочем
   дереве. Изменён, удалён, переименован = отказ. Новые файлы тестов допустимы. Исключения:
   список `allow_modified_tests` в конфиге. Глобы с `**` реализуй сам или через
   PurePath.full_match (3.13+); тесты на `**` обязательны.
5. Форма карточки: файл `$SYMPHONY_WORKFLOW_DIR/kanban/<ID>.md`; в состоянии Human Review/Done
   должны быть непустые разделы из `required_sections` (умолчание: `## Wiki Updates`,
   `## As-Is -> To-Be Report`). Нет раздела или он пуст = отказ.
6. Тесты проекта: `test_command` из конфига, `bash -lc` в рабочей папке, таймаут
   `test_timeout_s` (умолчание 900), отдельная группа процессов (start_new_session), при таймауте
   убивается вся группа. Подход возьми у `run_done_gate` из K02 (workspace.py). Код 0 = пройдено.

## Безопасность и закрытый режим
- Скрипт, конфиг и пример лежат вне рабочей папки агента. Агент их править не должен.
- `SYMPHONY_ISSUE_TITLE` — данные от агента: не использовать ни в каких командах и путях.
- ID карточки: `SYMPHONY_ISSUE_ID`, иначе basename рабочей папки; проверка `^[A-Za-z0-9._-]+$`,
  иначе отказ. Все subprocess — списком аргументов, без shell=True, кроме `test_command` (команда
  из доверенного конфига).
- Целевое состояние отката — из белого списка {`In Progress`, `needs_human`}.
- Любое необработанное исключение: в `gate` — код != 0; в `hook`, если состояние Done/Human Review,
  — всё равно откат, как при провале, плюс запись в журнал.

## Откат, счётчик, журнал (режим hook)
- Откат: `<symphony> board mv <ID> "<состояние>" --root $SYMPHONY_WORKFLOW_DIR/kanban`.
  Путь к symphony: ключ `symphony_bin` из конфига, иначе `<dirname($SYMPHONY_PYTHON)>/symphony`,
  иначе откат невозможен: запиши ошибку в журнал. После `board mv` перечитай карточку и убедись,
  что состояние изменилось; если нет, запиши ошибку в журнал.
- Заметка в карточку: найди штатный способ дописать раздел (команда `symphony board ...` или API
  трекера). Если штатного нет, допиши в конец файла атомарной заменой и объясни в отчёте.
- Счётчик: `$SYMPHONY_WORKFLOW_DIR/.ours-state/<ID>.json` (failures, last_reason, last_at).
  Каталог создавай вместе с внутренним `.gitignore` со строкой `*`. При провале failures += 1.
  Если failures >= `max_check_failures` (умолчание 3) — целевое состояние `needs_human`.
  Счётчик не сбрасывается.
- Журнал: `.ours-state/check.log` (время, ID, режим, исход, причина) — для утреннего отчёта.
