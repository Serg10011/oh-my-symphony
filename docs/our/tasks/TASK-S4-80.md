# S4-80 — причины изменений плана

## Решение 15.11.2026

Сергей попросил, чтобы любой ведущий оставлял запись с причиной, когда
отступает от согласованного или ранее объявленного плана. Запись называет
изменение и конкретную причину. Правило распространяется на способ работы,
распределение ролей и выбранные проверки. Ведущий также объясняет, почему
решил взять на себя подходящую для назначенного исполнителя часть ещё до
её передачи. Для коротких задач достаточно обычного отчёта о работе.

## Где появляется запись

- Новые сессии API с `execution` получают эту инструкцию независимо от
  профиля ведущего. Для API-исполнителя и самостоятельной работы используется
  версия 3, для подписного Gemini Flash — версия 4 с его правилом передачи.
  Причина входит в итоговый «Ответ ведущего».
- На маршруте `Plan` ведущий добавляет `## Plan Changes` к карточке при
  пересмотре описанного ранее плана. При итоговом `Verify` отклонения и
  причины входят в уже существующий `qa/final-check.md` задачи.

Подготовлено в `codex/s480-plan-changes` архитектурным чатом. Исторические
версии инструкций сохранены по номерам сессий. Правка готовится к включению
в общий выпуск. [Инструкция архитектору](../PROJECT-ARCHITECT.md#как-ведущий-распределяет-работу).

## Проверка

- Ruff прошёл. Проверено, что запись требуется у новых ведущих с Luna,
  Flash и без исполнителя. Промпты `Plan` и `Verify` дают руководителю
  места для записи в карточке и отчёте.
- Первые запросы OMS-11, OMS-13, OMS-16 и OMS-17 собраны из сохранённых
  сессий. Все четыре хеша совпали с журналами.

  на рабочей ветке, три повтора на базе `43454cb` также прошли.
- Расход API в проверках составил $0.
