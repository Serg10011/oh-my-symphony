## 1. Формат план-файла (предложение чата этапа; сделай ровно так, отступления — в PR)

Файл — `<доска>/docs/<ЗАДАЧА>/work/plan.toml` (в рабочей копии агента это `docs/<ЗАДАЧА>/work/plan.toml`: `docs/<ID>` — ссылка в папку доски, `pc.ARTIFACTS_DIR`). Хук читает **со стороны доски**, не из рабочей копии. Разбор — `tomllib` (стандартная библиотека). Неизвестный ключ — ошибка (как в `project.toml`: опечатка не должна пройти молча).

```toml
version = 1

[[subtask]]
key = "glossary"                       # [a-z0-9-]{1,32}, уникален в плане
title = "Добавить словарь терминов"    # одна строка, ≤ 80 символов: короткое действие + объект
level = "simple"                       # имя из [levels] project.toml, не выше уровня задачи
level_reason = "одна страница текста, кода нет"   # одна строка, обязательна
goal = """Что сделать, по существу (несколько строк можно)."""
criteria = ["Результат по существу 1", "…"]       # 1–5 строк (правило критериев из CLAUDE.md)
check = "/bin/bash /Users/…/symphony-projects/oms/test.sh"   # одна строка: чем проверить
paths = ["docs/our/GLOSSARY.md"]       # область файлов: 1–20 шаблонов путей от корня репозитория
blocked_by = []                        # ключи подзадач ВЫШЕ в файле
non_goals = ["…"]                      # необязательно, 0–5 строк
```

Проверки плана (каждая провальная — строка в `## Plan Failure`; собрать **все** причины, а не первую):
1. Файл есть, обычный файл (не ссылка), ≤ 64 КБ, разбирается `tomllib`; `version = 1`; есть хотя бы одна `[[subtask]]`; их не больше `max_subtasks`.
2. Ключи и типы полей — строго по схеме выше; длины и количества — как в комментариях; строки без управляющих символов (кроме переводов строк в `goal`).
3. `key` уникальны; `blocked_by` ссылается только на ключи **выше** в файле (это исключает циклы и даёт порядок создания); без ссылки на себя.
4. `level` есть в `[levels]` и не выше уровня задачи. **Порядок уровней** — порядок их объявления в `[levels]` `project.toml` (`tomllib` сохраняет порядок; в заготовке `simple` → `standard` → `complex` → `critical`); запиши это правило в комментарий заготовки. Уровень задачи — `level:` её карточки, иначе `default_level`; если нет ни того ни другого — ограничения нет. (`[levels]` пустой — не провал плана, а сразу `needs_human`, см. ниже.)
5. `paths`: относительные, без `..`, без ведущего `/`, не пустые; **ни один шаблон не попадает в запрещённые пути и контур контроля** — проверь функцией `check.forbidden_violations` (по самим шаблонам как путям; если шаблон со звёздочкой, проверь и его префикс до первой звёздочки) с `check.load_config(<доска>)`. Подзадача, которой заранее нечего делать в разрешённом, — ошибка плана, а не будущий отказ `check.py`.
6. Карточек `<ЗАДАЧА>-1 … <ЗАДАЧА>-N` на доске ещё нет (файлов `kanban/<ID>.md`); `[integration] enabled = true`.

**Сразу `needs_human`, без траты попытки плана** (решение архитектора: руководитель это не исправит; счётчик провалов не растёт): интеграция выключена; на доске уже есть хотя бы одна карточка `<ЗАДАЧА>-N`; `[levels]` в `project.toml` пуст. Эти условия проверяются **до** разбора плана; причина — в `## Plan Failure`, событие `rejected` с пометкой `needs_human: environment`. Всё остальное — провал плана и возврат в `Plan`.
