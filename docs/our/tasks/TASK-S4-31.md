# S4-31 — не выдавать прежний ID новой карточке

Сергей поручил продолжить после аудита 31.10.2026. Прежнее решение —
DECISIONS, «Порядок после шага 6», п. 3 от 27.10. История по ID сохраняется
штатно; исправляется повторная выдача номера после удаления карточки.
Прокрутка доски — отдельный оставшийся пункт, в эту задачу не входит.

База — `our-main @ c7c7536`, ветка `codex/board-id-reservations`.
Разработка и тесты — в отдельной рабочей копии. Запуск агентов, правка
живых досок, слияние и применение в это поручение не входят.

## Критерии приёмки

1. После удаления максимального номера и после перезапуска автоматическая
   выдача продолжает счёт. Счётчик хранится на доске под общей блокировкой.
2. Ручное создание не возвращает использованный ID другой карточке;
   параллельные процессы не получают одинаковые номера. CLI имеет путь
   автоматической выдачи без внешнего подсчёта `max + 1`.
3. Переход учитывает существующие карточки, прежние замки ID и сохранённую
   историю запусков, в том числе при внешнем `board_root`. История не очищается.
4. Повреждение журнала/истории и ошибка записи останавливают создание
   или удаление до потери карточки; прерывание может оставить пропуск,
   но не возвращает зарезервированный ID в оборот.
5. Новые регрессии, полный набор ядра, затронутые проверки `ours/` и ruff
   проходят. Отдельно описаны старые скрипты, предел восстановления старых
   ID и последствия для повторного создания фиксированных ID подзадач.
