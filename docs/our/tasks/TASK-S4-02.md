### 1. `ours/bin/inbox-runner` (+ логика в `ours/hooks/inbox_runner.py`)

Тонкая обёртка в `ours/bin/`, вся логика в `ours/hooks/inbox_runner.py` (по образцу `post_merge.py`: тесты импортируют функции и подменяют внешнее). Только стандартная библиотека, Python ≥ 3.11, сообщения для человека — по-русски простым языком.

```
ours/bin/inbox-runner [--main DIR] [--worktree-root DIR] [--interval СЕК] [--once] [--gh ПУТЬ] [--osascript ПУТЬ]
```

Служба в цикле смотрит каталог `<main>/tmp_workspaces/inbox/` (опрос раз в `--interval`, по умолчанию 3 с; без fswatch и сторонних пакетов). `--once` — один проход и выход (для тестов и ручной проверки). `--main` по умолчанию — основная рабочая копия репозитория, в котором лежит скрипт (как в `post-merge`). `--worktree-root` — каталог рабочих копий разработки, по умолчанию константа `/Users/helloworld10011/dev/oms-dev` (аргумент задаётся только в командной строке службы и в тестах, никогда — из файла).

**Ровно три команды-файла, больше ничего:**

- `<код>.run` — **сначала рабочая копия, потом Claude Code; это делает код службы, а не модель.** Содержимое файла: пустое, либо одна строка `model=<sonnet|opus|haiku>` (по умолчанию `sonnet`). Требование: рядом лежит обычный файл `<код>.md`. Порядок (решение архитектора):
  1. проверить, что ветки `dev/<код>` ещё нет (`git -C <main> show-ref --verify --quiet refs/heads/dev/<код>`) и что папки `<worktree-root>/<код>` нет. Если есть хоть что-то одно — **ничего не делать**, записать причину в отчёт (это то же правило «повтор не выполняется»), окно не открывать;
  2. `git -C <main> fetch origin our-main` — не трогает рабочие файлы основной папки, база всегда свежая;
  3. `git -C <main> worktree add --no-track -b dev/<код> <worktree-root>/<код> origin/our-main` (`--no-track` — чтобы ветка не была привязана к `our-main` и случайный `git push` без аргументов ничего не тронул);
  4. открыть новое видимое окно Терминала с командой
     `cd <worktree-root>/<код> && claude --model <модель> "Выполни задание из файла <main>/tmp_workspaces/inbox/<код>.md"`.
  Любой шаг упал — следующие не выполняются, причина и вывод `git` — в отчёт. Если рабочая копия создана, а окно открыть не удалось, копию не удалять: в отчёте напечатать готовую строку запуска, чтобы Сергей мог набрать её сам. Построение команд (шаги 1–4) — отдельные функции, чтобы их можно было менять и тестировать по одной.
- `<код>.merge` — внутри имя ветки (одна строка). Порядок:
  1. проверить, что есть **ровно один открытый** PR из этой ветки в `our-main` репозитория `Serg10011/oh-my-symphony`, и что ветка этого же репозитория, а не чужого форка: `gh pr list --repo Serg10011/oh-my-symphony --head <ветка> --base our-main --state open --json number,headRefName,headRepositoryOwner,isCrossRepository` (разбери JSON сам, не доверяя ничему лишнему);
  2. `gh pr merge <ветка> --repo Serg10011/oh-my-symphony --merge` (без `--admin`, без `--delete-branch`, без `--auto`);
  3. если слияние прошло — `ours/bin/post-merge` из основной папки (тем же Python, `sys.executable`; код возврата 0 и 2 — нормальные, 2 = часть действий отложена из-за карточек в работе; записать в отчёт).
  Если слияние не прошло — `post-merge` не запускать, причина в отчёте.

- `<код>.test` — **прогон проверок в рабочей копии** `<worktree-root>/<код>` (добавлено решением архитектора). Содержимое файла — пустое (любое содержимое → пропуск и запись в `_skipped.log`). Рабочая копия должна быть зарегистрирована в `git -C <main> worktree list --porcelain` на ветке `refs/heads/dev/<код>`; иначе — отказ в отчёте. Набор проверок **зашит в коде**, из файла не берётся:
  1. всегда: `python -m ruff check ours`, затем `python -m pytest ours/tests -q`;
  2. если ветка меняет `src/` или `tests/` (`git -C <копия> diff --name-only origin/our-main...dev/<код>` — есть путь, начинающийся с `src/` или `tests/`) — ещё `python -m ruff check src tests` и полный `python -m pytest -q`, **строго после** шага 1 и не параллельно с ним.
  Какой Python:
  - ветка **не** меняет `src/` — Python из `.venv` основной папки (`<main>/.venv/bin/python`); нет такого файла — отказ с понятным текстом в отчёте;
  - ветка меняет `src/` — **своё окружение в рабочей копии**: если `<копия>/.venv` нет, создать `python -m venv .venv` и `.venv/bin/pip install -e ".[dev]"` (иначе тесты проверят не тот код — та же ловушка, что у проекта `oms`); после установки проверить, что `symphony` импортируется из рабочей копии (`.venv/bin/python -c "import symphony; print(symphony.__file__)"` — путь внутри `<копия>`), иначе итог FAIL с объяснением.
  Как выполняется: каждая проверка — отдельный подпроцесс списком аргументов (без `shell=True`), `cwd` = рабочая копия, в **своей группе процессов**; окружение короткое и явное (`PATH` = `<bin выбранного .venv>:/usr/bin:/bin:/usr/sbin:/sbin`, `HOME`, `LANG`), **без переменных `SYMPHONY_*`** (в окружении службы лишние `SYMPHONY_*` дают ложные падения тестов). Таймауты: ruff — 300 с, `ours/tests` — 1200 с, полный `pytest -q` — 3600 с, создание окружения и `pip install` — 900 с; по таймауту и по SIGTERM службы группа процессов убивается, шаг считается проваленным. Упавшая проверка не прерывает остальные (кроме сбоя окружения): в одном отчёте нужна полная картина.
  Отчёт `outbox/<код>.test.log`: время, какой набор выбран и почему (список изменённых каталогов), какой Python, **полный вывод каждой проверки как есть и её код возврата**, в конце сводка по шагам и итоговая строка `ТЕСТЫ: PASS` или `ТЕСТЫ: FAIL`.
  **Повтор `.test` для того же кода разрешён** (в отличие от `.run` и `.merge`): тесты гоняют после каждой доработки. Перед записью нового отчёта старый `<код>.test.log` переименовывается в `<код>.test.<UTC-метка>.log`, ничего не затирается. Файл `.test` по-прежнему сначала забирается в `done/` (уникальное имя с меткой), потом выполняется. Команды очереди выполняются по одной: пока идёт `.test`, остальные ждут — это нормально.

**Безопасность (самое важное; каждый пункт — тест):**

- Содержимое файлов **никогда** не выполняется и не вставляется в оболочку как есть. Код команды берётся из имени файла и проверяется регулярным выражением `^[A-Za-z0-9][A-Za-z0-9-]{0,30}$`; расширение — строго `.run`, `.test` или `.merge` (регистр важен). Модель — только из списка `sonnet|opus|haiku` (сравнение целиком). Имя ветки — `^[A-Za-z0-9][A-Za-z0-9._/-]{0,80}$`, без `..`, без `//`, не заканчивается на `/` или `.lock`, не равно `our-main` и `main`.
- Репозиторий `Serg10011/oh-my-symphony`, базовая ветка `our-main`, имена трёх команд, набор проверок `.test` и список моделей — **константы в коде**, а не из файла и не из аргументов.
- Файл принимается, только если это обычный файл (не символическая ссылка, не каталог), размером ≤ 1 КБ, читается как строгий UTF-8, не менялся последние 2 секунды (защита от недописанного файла). Для `.merge` — ровно одна непустая строка; для `.run` — пусто или ровно одна строка `model=…`; для `.test` — пусто. Иначе — пропустить и записать в отчёт (один раз на файл, не на каждый проход).
- Команда для Терминала собирается через `shlex.quote` из проверенных частей; пути `<main>` и `<worktree-root>` — абсолютные без пробелов и спецсимволов (проверка шаблоном), `<main>` существует и это git-репозиторий. `origin`, `our-main` и префикс ветки `dev/` — константы в коде. В `osascript` команда передаётся **аргументом**, а не вставляется в текст скрипта: скрипт постоянный —
  ```
  on run argv
    tell application "Terminal"
      activate
      do script (item 1 of argv)
    end tell
  end run
  ```
  и запускается как `osascript -` со скриптом на stdin, команда — первым аргументом. Так экранировать нечего и вставить лишнее нельзя. Русский текст в команде должен дойти без искажений (проверь в тесте на уровне собираемых аргументов).
- Подпроцессы запускаются списком аргументов, без `shell=True`, с таймаутом (`git` и `gh` — 120 с, `post-merge` — 1800 с), `stdin` закрыт. `git` — по абсолютному пути `/usr/bin/git` (в окружении launchd короткий `PATH`).
- Пути к `gh` и `osascript` — абсолютные: по умолчанию `--gh` берётся из аргументов (при установке `inbox-runner-launchd` находит его через `shutil.which` и записывает в plist), `osascript` — `/usr/bin/osascript`. Нет файла по пути — понятный отказ, не падение.
- Неизвестный файл (не `.md` задания, не `.run` / `.merge`, не подходит под шаблоны) — пропустить, не трогать и записать в отчёт (`outbox/_skipped.log`: время, имя, причина). Файлы `<код>.md` — это задания, о них служба молчит. Каталог `done/` не обрабатывается.

**Учёт и защита от повтора:**

- Сначала файл **забирается**: `os.rename` в `inbox/done/<имя>.<UTC-метка>` (атомарно), и только потом выполняется команда. Если служба упала посреди — команда не повторится (лучше потерять, чем выполнить дважды).
- Отчёт о каждой команде — `<main>/tmp_workspaces/outbox/<код>.<команда>.log`: время начала и конца, что сделано по шагам, вывод `gh` и `post-merge` как есть, код возврата. Для `.run` и `.merge`, если такой лог уже есть, повторная команда с тем же кодом **не выполняется** (запись в `_skipped.log`: «повтор»); чтобы повторить — нужен новый код, опиши это в README. **Исключение — `.test`**: повтор разрешён, старый отчёт сохраняется с меткой времени (см. выше).
- Одна копия службы: файл-замок (`fcntl.flock`) в `tmp_workspaces/`. Вторая копия отказывает с понятным сообщением.
- Папки `inbox/done/` и `outbox/` создаются службой. Все файлы — права только владельцу.
- Самообновление: после выполненной `.merge` служба сравнивает хеш своих файлов (`ours/bin/inbox-runner`, `ours/hooks/inbox_runner.py`) с хешем при старте; если изменились — завершается с кодом 0, `launchd` (`KeepAlive`) запускает новую версию. **Перезапуск — только после того, как команда завершена и её отчёт полностью записан** (тест: отчёт на диске до выхода).
- Корректное завершение по SIGTERM (дописать отчёт текущей команды, потом выйти).

### 3. Тесты `ours/tests/test_inbox_runner.py`

**Все подпроцессы со скриптами `ours/` в тестах — только через `sys.executable`** (см. шаг 0). Временные папки (настоящий git-репозиторий для `<main>`), `osascript`, `gh` и `post-merge` — подменяемые функции (аргументы/поля, не monkeypatch глобалов), настоящий `osascript`/`gh`/`launchctl` не вызывать. Обязательные случаи:
- `.run` без модели → по порядку выполнены `fetch`, `worktree add --no-track -b dev/<код> <worktree-root>/<код> origin/our-main`, затем в `osascript` уходит команда `cd <worktree-root>/<код> && claude --model sonnet "Выполни задание из файла <main>/tmp_workspaces/inbox/<код>.md"`; с `model=opus` → `opus`; `model=gpt4`, `model=sonnet;rm -rf ~`, две строки, пробелы вокруг `=` → пропуск и запись в `_skipped.log`, ни один шаг не выполнен;
- `.test`: ветка не меняет `src/` и `tests/` → ровно два шага в этом порядке (`ruff check ours`, `pytest ours/tests -q`), Python из `<main>/.venv`, `cwd` = рабочая копия; ветка меняет только `tests/` → четыре шага, Python основной папки; ветка меняет `src/` → создание `.venv` в копии (`venv`, `pip install -e ".[dev]"`, проверка пути `symphony`) и четыре шага с Python копии; нет `<main>/.venv` / копия не зарегистрирована в `worktree list` / ветка копии не `dev/<код>` → отказ без запуска проверок; в окружении подпроцессов нет `SYMPHONY_*`; одна проверка упала → остальные всё равно выполнены, итог `ТЕСТЫ: FAIL`, коды возврата в отчёте; таймаут → группа процессов убита, шаг провален; `.test` с непустым содержимым → пропуск; **повтор `.test` для того же кода выполняется**, старый отчёт переименован в `<код>.test.<метка>.log`, новый записан; файл забран в `done/` до запуска проверок. Запуск подпроцессов — подменяемая функция, настоящие `ruff`/`pytest`/`pip` в тестах не вызывать (и `python -m venv` тоже подменить).
- `.run` без `<код>.md` → пропуск;
- `.run`: ветка `dev/<код>` уже существует / папка `<worktree-root>/<код>` уже есть → ничего не выполнено (ни `fetch`, ни окна), причина в отчёте; `fetch` упал → `worktree add` и окно не вызваны; `worktree add` упал → окно не открыто; окно не открылось после успешного `worktree add` → рабочая копия на месте, в отчёте готовая строка запуска; на настоящем git во временных репозиториях (bare «origin» с веткой `our-main`) проверь: ветка создана от `origin/our-main`, без upstream (`git rev-parse --abbrev-ref dev/<код>@{upstream}` падает), основная папка не изменилась (`git status` и HEAD до и после);
- имя кода с `;`, пробелом, `$()`, `..`, кириллицей, слишком длинное; регистр расширения `.RUN` → пропуск;
- команда в `osascript` — аргумент, текст скрипта константа; собранная команда содержит именно `cd <worktree-root>/<код> && claude --model … "Выполни задание из файла <main>/tmp_workspaces/inbox/<код>.md"`;
- `.merge`: нет открытого PR / два PR / PR из чужого форка / база не `our-main` → слияние не вызвано; один подходящий PR → вызваны `gh pr merge <ветка> --repo Serg10011/oh-my-symphony --merge` и затем `post-merge`; слияние упало → `post-merge` не вызван; `post-merge` вернул 2 → в отчёте отмечено, служба не падает; ветка `our-main`, `main`, `--admin`, `a b`, `x;y`, `-x`, `a..b` → пропуск;
- символическая ссылка вместо файла, файл > 1 КБ, не UTF-8, свежий (менее 2 с) файл → не обработан;
- файл забран в `done/` до выполнения команды (подмена, которая проверяет наличие файла в `done/` в момент вызова); повторная команда с тем же кодом при существующем логе не выполняется; после падения команды файл остаётся в `done/`, второй проход ничего не делает;
- неизвестные файлы пропускаются один раз (лог не растёт на каждом проходе), `.md` и `done/` — молча;
- замок: вторая копия отказывает; самообновление: смена хеша после `.merge` → код возврата «перезапуск»;
- `inbox-runner-launchd`: содержимое plist (метка, аргументы, `KeepAlive`, абсолютные пути), «без изменений» при втором запуске, отказ без `gh`, `launchctl` не вызывается;
- один тест целиком как подпроцесс: `ours/bin/inbox-runner --once` на временных папках (настоящий git, bare «origin») с поддельными `gh` (скрипт-заглушка по абсолютному пути) и `osascript` (заглушка записывает аргументы в файл); на не-macOS нет `/usr/bin/osascript` — тест передаёт `--osascript` заглушку.
