Исправь найденные S4-59 недостатки кеширования OpenAI, поиска по проекту
и диагностики сети. Корректный большой пакет чтений не должен обрывать
всю задачу. Сохрани историю, разрешённые границы проекта, учёт расходов
и возможность продолжить остановленную S4-54 без повторной оплаты уже
полученного ответа. Не выдавай локальную проверку кеша за измеренную экономию.

## Назначение

найденные недостатки. Разрешённое продолжение получило восемь ответов Luna,
после чего 55-й запрос остановился на пакете из 34 корректных чтений при
внутренней границе 32. Для завершения S4-54 эта доработка стала необходимой.

Исполнитель — текущий чат, согласованное усилие max; для анализа совместимости
рекомендована Astra / max. Фактическая смена модели помощником не выполнялась.
Новых чатов и субагентов нет. Ветка codex/api-spending-completion от
our-main 8ee71bf6655e39ed4c880faf68c579a8d9633e6f.

Кеш проверяется для обоих OpenAI-профилей, Luna и Sol. Прежние запросы
должны воспроизводиться прежним способом; новая политика закрепляется
в каждой новой записи запроса. Поиск остаётся чтением разрешённых Git-файлов.
Автоматический повтор платных запросов не разрешён. Платное продолжение
после новой остановки и слияние будущего PR требуют отдельного подтверждения.

## Уточнения параллельной проверки

В старых экспериментах S4-38/S4-39 использовались чаты Codex, а не этот
API-клиент, появившийся 03.11.2026. Сохранённый кеш Luna — 98,313% входа,
Sol Medium в S4-39 — 98,567%. Найденная S4-59 ошибка не объясняет их исход.

Четыре окна Keychain подтверждены скриншотами Сергея: две разные формулировки
для каждого из двух ключей. В операторском запуске одна команда чтения на
провайдера. Точная причина двух системных подтверждений не установлена;
число окон не равно числу API-вызовов. Доступ Keychain не расширяется.
