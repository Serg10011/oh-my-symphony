## Критерии приёмки

1. Обычная карточка и карточка-задача в Human Review получают проверенную
   доставку: `merge-tree` / `commit-tree`, временная detached-копия вне
   проекта и доски, общие с project-doctor `setup.sh` и полный `test.sh`.
   Ветки и рабочие папки карточек сохраняются; временная копия убирается.
2. Проверяются запрещённые пути, ключи, существующие тесты, форма карточки
   и неизменность проверенного дерева. Итоги сравниваются с историей S4-25
   для текущего конца базы; успешный замер кандидата добавляется в историю,
   не заменяя последний замер базы. Процессы ограничены по времени и
   завершаются вместе с дочерними; очередь получает достаточный бюджет.
3. Конфликт или провал проверки: пуша и PR нет, карточка идёт в needs_human
   с причиной, списком файлов или хвостом лога без ключей. Изменение базы,
   источника, состояния карточки или доказательства проверки за время
   прогона останавливает доставку до отправки.
4. Публикация остаётся только в `deliver/<ID>` указанного репозитория,
   без force. Продолжение после сбоя PR использует тот же проверенный
   коммит, не повторяя пуш; связь исходного дерева и дерева доставки
   сохраняется для одноразовой приёмки Done.
5. Настоящие временные Git-репозитории и подменённый GitHub подтверждают
   успешные и аварийные сценарии, неизменность веток и уборку. Ruff и полный
   `ours/tests` проходят. Реальные доски и агенты не запускаются; PR — в
   our-main, слияние и применение предъявляются Сергею после приёмки.

Существующие проверки отказа при сдвинутой базе/сокращённом прогоне и
ожидание бюджета очереди меняются только там, где прежнее поведение прямо
заменяется этой задачей. Остальные проверки сохраняются.
