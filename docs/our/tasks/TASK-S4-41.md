## Критерии (5)

1. Сгенерированный WORKFLOW объявляет Merging как состояние без агента,
   сохраняет рабочую копию и разрешает зависимости только по Done.
   Прошедшие Verify подзадачи направляются в Merging, родитель сохраняет
   Document → Human Review. Модели, лимиты и оплата не меняются.
2. Механические проверки и интеграция обрабатывают Merging. Done появляется
   после проверенного коммита и успешного слияния; конфликт ведёт к человеку
   без изменения integration-ветки. Старый путь подзадач через Human Review
   сохраняется; обычная карточка не считается подзадачей по одному статусу.
3. Есть явное продолжение прерванной сборки без агента: повторная проверка,
   блокировки и проверка принадлежности рабочей копии; отказ при несохранённых
   изменениях. Повтор после слияния не создаёт второй коммит того же результата.
4. Тесты используют временные настоящие Git и проверяют успешный путь,
   конфликт, отказ проверок, прерывание, совместимость и отсутствие диспетчеризации
   Merging. Ruff ours и полный ours/tests проходят. Старые проверки не ослабляются.
5. Задание, решения, профиль, коммиты, проверки, ограничения и PR сохраняются
   в истории. Реальные карточки, агенты, службы и post-merge не запускаются.
   Приёмка, слияние и применение — отдельные факты, разрешения пока нет.
