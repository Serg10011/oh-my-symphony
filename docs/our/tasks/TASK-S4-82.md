# S4-82 — один прогон на выпуск

16.11.2026 Сергей согласовал штатную установку по сохранённому отчёту.
Цель — выполнить полный набор один раз для собранной версии и использовать
тот же результат при установке. Приёмка выпуска остаётся за оператором.

## Поведение

Архитектор запускает `project-doctor --record-release` из рабочей копии
выпуска. Одна пробная копия фиксирует коммит, дерево, хеши `setup.sh`
и `test.sh`, результаты и время фактического прогона. Для установки
используется `post-merge --verified-release`. Он проверяет выбранную доску
и обе Git-копии перед обновлением. После сверки остаются настройка,
проверка конфигурации и ожидание ответа работающей доски после перезапуска.
Занятая очередь откладывает применение. Неуспешная проверка конфигурации
сохраняет возможность повтора с тем же отчётом.

Из чистого прогона берутся фактические данные нового замера. Исторический
формат с адресной перепроверкой сверяется по журналу первого прогона и
точному списку повторённых случаев. История замеров при этом сохраняется.
[Мануал](../../../ours/README.md#установка-по-готовому-отчёту).

## Первое применение

После согласования точного выпуска для первой установки используется код
из его проверенной рабочей копии. На Mac с текущей привязкой SSD из
каталога `work`, при `REPORT` с путём к готовому отчёту:

~~~sh
dev/oh-my-symphony/.venv/bin/python -IB -c '
import sys
sys.path.insert(0, "development/oh-my-symphony/ours/hooks")
import post_merge
sys.path.insert(0, "host")
import after_merge
raise SystemExit(after_merge.main(sys.argv[1:]))
' --project oms --verified-release "$REPORT"
~~~

В последующих выпусках используется обычный вызов `host/after_merge.py`
с тем же параметром отчёта.
