# S4-57 — аварийные пределы API-сессии с большим запасом

Убери тесную границу числа API-обращений и связанные ограничения короткой
пробы. Новые сессии должны получать большой технический запас для работы,
сохраняя конечную защиту от бесконечного выполнения, учёт расхода и явно
заданные ограничения. Старые согласованные сессии и их историю не увеличивай
задним числом.

## Первый вариант — история, пересмотрен ниже

Новые defaults: 1000 общих модельных ответов, 32768 выходных токенов
на ответ, 2097152 общего выхода, 1 МиБ на запрос. Число обращений —
аварийный предел, не ожидаемая длина задачи или цель для модели.
Явно допускаются max_calls 1–100000 и общий выход до 100000000;
граница 64 и связанный с ней максимум общего выхода снимаются.

32768 — уже поддержанный локальным адаптером максимум одного ответа.
Общее сетевое ожидание данных генерации увеличивается со 120 до 600 секунд
между чтениями из соединения, а не как общий срок ответа;
подключение/запись/пул и предварительные запросы сохраняют 120 секунд.
Повторов при ошибке нет. Разбор ответа, допуски инструментов, предел
состояния 16 МиБ и транспортные размеры не расширяются.

Нормализованные параметры сохранённых сессий остаются прежними.
Default применяется только к отсутствующим полям нового init; явные
значения, включая небольшие согласованные пробы, исполняются точно.
Денежный budget по-прежнему необязателен; заданный обязателен к исполнению.
Новые defaults сами по себе не разрешают платный запуск.
