## Зачем

После программного `Done` (S4-12) ядро само запускает `check.py gate` в рабочей копии подзадачи — и тесты идут второй раз на том же содержимом (≈5–10 минут впустую на каждую подзадачу), а нестабильный тест может отказать уже после вливания: код в интеграционной ветке, карточка в `Blocked`. Решение архитектора: шлюз **не гоняет тесты повторно, если дерево проверяемого коммита совпадает с деревом, которое прошло `check.py hook` и было влито**. Схлопывание коммитов ядром (`finalize_delivery_history`: soft reset к базе + один коммит) дерево не меняет, поэтому сравнение по дереву надёжно. Не совпало — полный прогон, как сейчас.

## Что сделать

### 1. `integrate.py` — запись «влито» с деревом

В исходе `done` (влито или «без изменений»), **после** успешного `board mv Done`, писать `<доска>/.ours-state/<ID>.merged.json` (через `check._write_atomic`): `{"tree": <mark["tree"]>, "commit": <sha нового коммита или null>, "task", "branch", "source": "symphony/<ID>@<sha>", "at"}`. Если `Done` не поставился — запись **не** писать (шлюз тогда не придёт, а если придёт позже руками — пусть гоняет тесты). В событии `done` добавить поле `merged_record: written`.

### 2. `check.py gate` — пропуск тестов по совпадению дерева

Только в режиме `gate` (в `hook` ничего не меняется). В `run_checks` после быстрых проверок (конфиг, база, запрещённые пути, изменённые тесты, разделы карточки — они **выполняются всегда**, они дешёвые) и до `run_tests`:
- если `ctx.mode == "gate"` и есть `<ID>.merged.json` с полем `tree`, и `worktree_tree(ctx.workspace)` (та же функция, что в хуке: содержимое диска, временный индекс) **равно** этому `tree` — тесты не запускать; результат `Result(True, [], "", cfg)` с пометкой: в отчёте шлюза строка `tests skipped: tree <12 знаков> passed check.py hook and was merged into <branch> (<commit|no changes>)`, в событии `gate` → `pass` с `reason` того же содержания и полем `tests: skipped`;
- запись `.merged.json` после использования удалить (одноразовая, как `.pass.json`); если дерево не совпало — **тоже удалить** и написать в событие `tests: full` с причиной «tree differs from the merged one» — второго шанса у записи нет;
- нет записи — всё как сейчас (`tests: full` в событие добавлять не обязательно, но если добавляешь — одинаково во всех ветках).
Пропуск относится только к тестам: при провале быстрых проверок шлюз отказывает, как и раньше, и запись тоже удаляется. `Result` можно расширить полем `tests_skipped: bool` (по умолчанию `False`), чтобы `_format_report` и `gate_main` знали, что писать; `hook` это поле не ставит.

### 3. Две мелочи из приёмки S4-12 (`integrate.py`)

- `_dirty_files`: исключать те же пути, что штатный блок и `worktree_tree`, — `git status --porcelain -z --untracked-files=all -- <check.STAGE_PATHSPEC>` (`.`, `:(exclude)kanban`, `:(exclude).symphony`). Тест: нетронутый файл внутри `.symphony/` не считается грязью; файл в корне — считается.
- `_run_hook`: карточка не в `Human Review` → выйти **молча** (без события `skipped`), иначе при включённой интеграции каждый ход каждой карточки пишет строку в `check.log`. Остальные `skipped` (не подзадача, запись базы без `task`, блокировка, нет отметки, дерево не совпало, грязная копия) — как были. Обнови тест, который ждал событие для карточки не в `Human Review`, если такой есть (это единственная допустимая правка существующего теста; объясни в PR).

### 4. Тесты (`ours/tests/test_check.py`, `ours/tests/test_integrate.py`; существующие не менять, кроме указанного в п. 3)

- `integrate hook` → `done`: появился `.merged.json` с нужными полями, `tree` равен `HEAD^{tree}`; при `board mv` без эффекта записи нет.
- `gate` с записью и тем же деревом: тесты **не запускались** (в `test_check.Env` тестовая команда ставит маркер — маркера нет), шлюз `PASS`, в отчёте строка `tests skipped`, событие `gate pass` с `tests: skipped`, запись удалена. Отдельно: то же после имитации схлопывания ядра (`git reset --soft <base>` + новый коммит в рабочей копии) — дерево то же, пропуск работает.
- `gate` с записью и другим деревом (файл правлен после вливания): тесты запускались (маркер есть), запись удалена, событие `tests: full`.
- `gate` без записи — как раньше (существующие тесты шлюза проходят без изменений).
- `gate` с записью, но провал быстрой проверки (например, изменён существующий тест): отказ, тесты не запускались, запись удалена.
- `hook` с записью `.merged.json` — не пропускает (гоняет тесты), запись не трогает.
- Мелочи из п. 3.
