## Зачем

Решение Сергея от 27.10.2026. Команда `.run` открывает новое окно Терминала с Claude Code, а закрывает его Сергей руками после каждой задачи (`/exit`, закрыть вкладку). Окна копятся, это лишние действия, а сессия остаётся сидеть в папке рабочей копии, которую `post-merge` после слияния удаляет. Надо, чтобы очередь сама закрывала окно задачи, **когда задача влита**. После `.test` окно не трогать: после «проверь» в той же сессии могут понадобиться правки.

## Что сделать

### 1. `.run`: запомнить окно

- `TERMINAL_SCRIPT` (сейчас `do script (item 1 of argv)`, вывод — ссылка вида `tab 1 of window id 18816`): вернуть **номер окна** и **`tty` вкладки**, например две строки `window_id=<число>` и `tty=/dev/ttysNNN` (`set t to do script …`, `tty of t`, номер окна — из ссылки на вкладку или `id of window of t`; выбери надёжный способ и опиши в PR). Формат вывода разбирать строго; что не разобралось — окно не записывается, в отчёте строка «окно не записано: …», запуск при этом **не** считается неудачным.
- Запись `tmp_workspaces/outbox/<код>.terminal.json`: `{"code", "window_id", "tty", "opened_at"}`. Пишет только `.run`, после успешного открытия окна.
- В отчёт `.run` — строка `Окно: id <N>, tty <tty>`.

### 2. `.merge`: закрыть окно после успешного слияния

Место — в `do_merge`, **после строки «PR влит.» и до шага `post-merge`** (`post-merge` убирает рабочую копию). Отдельный шаг отчёта «закрыть окно Claude Code». Порядок:

1. Код задачи — из имени файла команды (`<код>.merge`); ветка `dev/<код>` уже проверена. Прочитать `<код>.terminal.json`. Нет записи или запись испорчена → строка «окно не записано — закрой сам, если открыто» и дальше.
2. **Проверка, что это то самое окно**: у окна `window_id` сейчас есть вкладка с тем же `tty` (osascript). Не совпало, окна нет, Терминал не запущен → ничего не закрывать, строка с причиной.
3. **Остановить Claude Code в этой вкладке вместе с его потомками**: найти процессы на этом `tty` (`ps -t <tty> -o pid=,ppid=,command=`), у которых в командной строке есть `claude` **и** полный путь к файлу задания `…/tmp_workspaces/inbox/<код>.md` (он есть в строке запуска — `terminal_command`). Построить **дерево потомков** каждого найденного процесса по `ppid` из одного снимка `ps -A -o pid=,ppid=,command=` (команды и вспомогательные серверы, которые запустил Claude Code, могут сидеть и на другом `tty` или без него). `SIGTERM` всему дереву (корень и потомки), подождать до 10 с, оставшимся **из этого же дерева** — `SIGKILL`. Всё, что не входит в дерево найденного процесса, не трогать никогда; оболочку вкладки (`zsh`/`bash`, родитель Claude Code) не трогать. Причина (решение Сергея): если потомки останутся на вкладке, Терминал спросит подтверждение, и окно не закроется.
4. **Закрыть окно**: `tell application "Terminal" to close window id <N>`. Если Терминал всё-таки спросил подтверждение или закрыть не удалось (на вкладке остался другой процесс) — ничего не делать силой, строка «окно не закрыто: …, закрой сам».
5. Удалить `<код>.terminal.json` только если окно закрыто.

**Любая неудача шага 2–5 не мешает слиянию и `post-merge`**: только строка в отчёте, код возврата команды прежний. Таймауты osascript — `OSASCRIPT_TIMEOUT_S`. Все внешние вызовы — через `Ops` (как `proc`/`terminal`), чтобы тесты их подменяли; `osascript` — путь из `Settings`. Скрипты AppleScript — константами, данные — только через `argv` (как сейчас `TERMINAL_SCRIPT`), никакой подстановки текста в скрипт.

### 3. Чего не делать

- Не закрывать окна после `.test`, при отказе `.merge` и при неудачном `gh pr merge`.
- Не закрывать окна, которые открыла не очередь (нет записи `.terminal.json`).
- Не менять `post_merge.py` и логику уборки рабочих копий.

## Тесты (`ours/tests/test_inbox_runner.py` — новые тесты; существующие не менять)

- `.run`: вывод подменённого osascript разбирается, пишется `<код>.terminal.json`, строка в отчёте; неразборчивый вывод — записи нет, запуск успешен.
- `.merge` успешный: порядок шагов — PR влит → закрыть окно → `post-merge` (по журналу подменённых вызовов); процессу Claude Code на нужном `tty` ушёл `SIGTERM`, окно закрыто, запись удалена.
- **Настоящие процессы**: «claude»-заглушка (например `python -c` с аргументами `argv`, похожими на запуск: `claude … …/inbox/<код>.md`), которая сама запускает дочерний процесс (а тот — внука), — функция остановки завершает заглушку **и всех её потомков**; процесс без пути к заданию, с другим кодом и процесс вне дерева (например родитель заглушки, играющий роль оболочки) — не трогает. Потомок, игнорирующий `SIGTERM`, завершается `SIGKILL` после ожидания (ожидание в тесте — подменённое или короткое).
- `tty` окна не совпал / окна нет / записи нет / osascript упал — окно не закрывается, `post-merge` всё равно запущен, в отчёте причина.
- Неудачный `gh pr merge` и отказ `.merge` — шаг закрытия не вызывается.
