# S4-73 — Sol и Gemini Flash в одной команде

Дата назначения — 08.11.2026. 09.11 пара установлена на OMS в `bef60fa7`
через PR №117. Первая реальная карточка OMS-12 завершила выполнение до Verify.
Подготовка шла на Astra/max, интеграцию ведёт Sol 6.1.

## Задание

Подключить к обычной карточке конвейера ведущего Sol через бонусный OpenAI API
и исполнителя Gemini Flash через подписку Antigravity. Sol должен самостоятельно
вести задачу, поручать подходящую реализацию Flash, проверять и объединять
результат. При затруднении или явном запросе архитектора он повышает усилие
до max, продолжая текущую работу с сохранённым контекстом. Доска показывает
назначение, состояние работы, результат и расход каждого участника.

Приоритет — полезная реальная работа исполнителя и небольшой объём доработок
ведущего. Первое задание выбирается из настоящих небольших задач проекта.

## Подтверждённое назначение

| Роль | Модель и усилие | Доступ |
|---|---|---|
| Ведущий разработчик | `gpt-6.1-sol / high`, повышение до `max` | OpenAI Responses API, организация с бонусными кредитами Сергея |
| Исполнитель | `gemini-3.8-flash-high` | Antigravity, включённая квота Google AI Pro через Jio |

Сергей уточнил, что ведущий сам оценивает затруднение. Архитектор проекта
также может явно запросить max. В истории нужны причина, инициатор и точка
применения нового усилия. Обычное назначение новой задачи — high.
В ветке подготовлена явно включаемая политика `high-to-max` и инструмент
ведущего `raise_lead_effort`. Архитектор может назначить max перед запуском;
отдельной команды внешнего чата для смены усилия во время запроса пока нет.

Чат проекта отвечает за архитектуру и разработку подключения.
Sol в конвейере получает контекст проекта из доступных файлов и поручения.
Пара исполняет минимальное ТЗ по существующим правилам S4-48 и S4-66.

## Границы блока и приёмка

1. Обычный путь карточки использует назначенную пару, видимую в настройках
   доски и карточке. Старые сессии сохраняют своё назначение и историю.
2. Sol передаёт Flash работу в разрешённой рабочей копии, получает фактический
   результат и проверяет его. Ограничения путей, команд и приёмки действуют
   для подписного исполнителя так же, как для нынешней команды.
3. Повышение high → max сохраняет текущую историю и файлы, отражается в учёте.
   Технический сбой, исчерпание квоты или отказ доступа обрабатываются по
   своей причине. Повтор оплаченной попытки сохраняет отдельное подтверждение.
4. Расход Sol учитывается по фактическим API-ответам. Для Flash сохраняются
   доступные сведения о квоте и токенах. Неизвестные значения обозначаются
   явно. Используется включённая квота Google с ожиданием восстановления
   при её исчерпании. Проект API, остаток и срок бонусов сверяются перед пробой.
5. Команда проходит проверку передачи задания, остановки и сохранения результата
   через штатные этапы доски. Реальная проба получает отдельное назначение
   карточки и подтверждение расхода по действующим правилам проекта.

## Что подтверждено при подготовке

- В `ours/hooks/api_executor.py` есть `sol-lead` для `gpt-6.1-sol` через
  Responses API. Базовое усилие профиля medium, переопределение на high и max
  уже поддержано для задания до запуска. Изменение усилия внутри сессии
  требует отдельного механизма.
- `ours/hooks/api_session.py` и выбор команды пока допускают исполнителя
  `luna-worker` либо работу без исполнителя. Подписного Flash в этом цикле
  ещё нет. Общие инструменты, рабочую копию, проверки и историю переиспользуем.
- В ядре сохранён адаптер `src/symphony/backends/agy.py` для самостоятельного
  CLI-агента. Это полезная прежняя заготовка. Работа подписного исполнителя
  внутри API-команды требует границы доступа и передачи результатов.
- Проверенная конфигурация OMS использует `api-settings.json`, пару
  `deepseek-lead` + `luna-worker` и режим economy. Реальный маршрут OMS-11
  завершён в Done. Его разделение работы и расходы сохранены в
  [REPORT-60](../reports/REPORT-60.md).
- В текущем сеансе Antigravity 1.5.0 показал Gemini 3.8 Flash с уровнями
  high, medium и low. Список отдельной ACP-сессии подтвердил Flash.
  Запрос задачи модели не отправлялся. Квота и фактический тариф аккаунта
  этими проверками не подтверждены. Предположение о влиянии Jio сохраняет
  статус предположения.

Прямые запросы Responses API входят в условия бонусов OpenAI. Бонусы
применяются в связанной организации и имеют срок действия. Максимальный
уровень рассуждений Flash в Antigravity называется high. [Бонусы OpenAI](https://developers.openai.com/api/docs/guides/chatgpt-api-credits) ·
[Sol 6.1](https://developers.openai.com/api/docs/models/gpt-6.1-sol) ·
[Модели Antigravity](https://antigravity.google/docs/models) ·
[Квоты Antigravity](https://antigravity.google/docs/plans).

09.11.2026 Сергей разрешил разработку («го») и спросил про остаток квоты
Gemini. Подготовлены переход усилия Sol, учёт в журнале и отчёте,
показ права повышения перед подтверждением и текущего усилия в карточке.
Смена политики отменяет прежнее подтверждение условий; старые сессии
сохраняют фиксированное усилие. Подготовлен запуск диагностики Antigravity

интерактивном `/usage` сохранены в DEVELOPMENT. Затем найден официальный
источник автоматических данных в строке состояния. Подготовлен и проверен
сборщик без запроса модели: на CLI 1.5.3 в 00:25 МСК 09.11 оба остатка Gemini

вывод на доску ещё предстоит. Повтор проверки инструментов на 1.5.3

Исходный коммит назначения `977f1c2`; подготовленная часть реализации —

Код **`18505cc`** и уточнение учёта **`1fd1cf8`**, ruff `ours` прошёл;
