## Что наблюдалось на локальной пробе

Мок-бэкенд, файловая доска, `stage_contracts: auto`, `terminal_states: ["Human Review", needs_human, Done, Blocked, Archive]`:

- Хук `after_run` завершился с exit 1, карточка, переведённая из Todo сразу в Done без каких-либо разделов, осталась в Done. Контракты этапов не остановили.
- Ядро дописало в карточку «delivery: Done alone does not confirm target merge or workspace cleanup.», рабочую папку удалило, ветку `symphony/<ID>` оставило.
- Для Blocked ядро при старте сохраняет рабочую папку (лог `startup_terminal_cleanup_preserved_blocked_workspace`), для `needs_human` — нет.

## Вопросы (в порядке важности)

1. Все пути, которыми карточка может оказаться в Done: правка файла агентом, `symphony board mv`, клавиша «Confirm done» в TUI, веб-API/веб-доска, автоматические переносы ядра. Для каждого: какой код выставляет статус и проходит ли он через одну общую точку, где можно поставить проверку.
2. Где и когда вызывается `evaluate_contract` (и родственные проверки). Почему переход Todo→Done без доказательств не был остановлен? Срабатывают ли контракты при переносе в терминальный статус, при переносе вне агента, при `stage_contracts: on`?
3. Остаётся ли проверка рабочей при нашей конфигурации (`needs_human` в `terminal_states`, порядок статусов)? Если для нашей доски нет одной общей точки, остановись и опиши варианты, не придумывай обход.
4. Что происходит при ненулевом коде `after_run`: есть ли хоть какой-то след (лог, событие, поле)? Можно ли отличить «хук упал» от «хук отработал»?
5. Минимальное место для `agent.done_gate_command` (закрытый по умолчанию: скрипт упал, завис, не найден или вернул ошибку — в Done не проходит): файлы и функции, оценка объёма, какие тесты нужны (успех, провал, таймаут, нет команды). Что он должен получать на вход (ID, путь к рабочей папке, ветка) и куда писать причину отказа.
6. Что удаляет рабочую папку при переносе в `needs_human` и Done, и можно ли это настроить, чтобы папка `needs_human` сохранялась, как у Blocked? Куда при этом попадает работа агента (`auto_commit_on_done`) и где останется диагностика.
