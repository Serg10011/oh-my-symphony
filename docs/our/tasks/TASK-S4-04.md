## Что сломалось (факт из настоящего запуска, 26.10.2026)

Первая настоящая команда `.run` (`S4-03.run`) создала рабочую копию, но на шаге «открыть окно Терминала» в отчёте оказалось: `ВНУТРЕННЯЯ ОШИБКА: ValueError('Cannot send input after starting communication')`. Причина — `ours/hooks/inbox_runner.py`, функция `run_process`: в цикле ожидания вызывается `proc.communicate(input=stdin_text, timeout=0.5)`. Если процесс не завершился за 0,5 с (так было: `osascript` ждал ответа на запрос macOS о разрешении), первый вызов падает с `TimeoutExpired`, а второй вызов с тем же `input=` — с `ValueError`. Исключение вылетело из `run_process`, процесс `osascript` остался без присмотра. Тесты этого не поймали: все их подмены отвечали мгновенно.

## Что сделать

1. В `run_process`: `input` передавать только при первом вызове `communicate` (дальше — вызовы без `input`), как требует документация `subprocess`. Любой другой путь выхода с исключением внутри `run_process` (включая это) должен убивать группу процессов (`os.killpg(..., SIGKILL)`) и не оставлять запущенный дочерний процесс: оформи через `try/finally` или `except BaseException` с повторным подъёмом после уборки. Поведение остальных веток (таймаут, SIGTERM службы, нет программы, закрытый stdin) не менять.
2. В `Runner.handle` и в других местах, где пишется `ВНУТРЕННЯЯ ОШИБКА: …`, добавить в отчёт полный текст трассировки (`traceback.format_exc()` в блок вывода отчёта), чтобы следующая такая ошибка читалась без догадок.
3. Просмотри остальной `ours/hooks/inbox_runner.py` и `ours/hooks/post_merge.py` на тот же класс ошибок (повторный `communicate(input=…)`, неубитый дочерний процесс при исключении); найденное исправь тем же способом, о ненайденном скажи в PR.
4. Тесты в `ours/tests/test_inbox_runner.py` (новые, существующие не менять):
   - дочерний процесс, который читает stdin, ждёт ~1,5 с и печатает прочитанное: `run_process(..., stdin_text="...")` возвращает код 0 и вывод содержит этот текст (раньше — `ValueError`);
   - то же для `open_terminal` с поддельным `osascript`-скриптом, который ждёт ~1,5 с: возвращает `(True, …)` и записывает аргумент;
   - исключение внутри ожидания (подмени `communicate` так, чтобы второй вызов поднимал исключение): дочерний процесс убит, исключение поднято дальше (проверь, что процесс не жив);
   - внутренняя ошибка в `Runner.handle` попадает в отчёт вместе с трассировкой.
   Все подпроцессы со скриптами — только через `sys.executable`; тесты должны проходить и в среде `env -i HOME="$HOME" PATH=/usr/bin:/bin:/usr/sbin:/sbin`.
