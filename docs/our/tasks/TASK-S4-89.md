# S4-89 — чтение фрагмента из результата поиска

20.11.2026 Сергей согласовал следующий шаг по экономии Sol соло.
В [соло-прогоне OMS-25](TASK-OMS-25.md#повтор-на-sol-соло) шесть
команд чтения через оболочку вернули 75 772 байта из 118 422 байт
всех ответов инструментов. У поиска уже были путь и номер строки,
а чтение файла принимает позицию в символах.

В новых сессиях Sol 6.2 соло версия правил 11 получает для совпадений
в доступном тексте `read_hint` с позицией и размером фрагмента.
Sol передаёт путь и подсказку в `read_project_file`. До 20 соседних
строк с каждой стороны помогают увидеть контекст. При длинной строке
фрагмент ограничен обычным пределом чтения в 4 096 символов и включает
совпадение. `next_offset` позволяет дочитать файл, а повторный поиск
после правки даёт позицию на актуальной версии. Действуют разрешённые
пути карточки. Предыдущие версии сессий читаются по своим правилам.

## Проверка на копии

Сохранённый поиск OMS-25 на базе `d17724d86` нашёл ту же строку 387
в панели расходов. Ответ поиска вырос с 351 до 402 байт. Переход по
подсказке дал 41 строку за 3 460 байт, общий объём двух ответов
составил 3 862 байта. Продолжение вернуло следующий участок файла.
Этот замер относится к одному фрагменту задачи.

Через обычный маршрут сессии с подставными ответами проверены
новая подсказка, чтение и старая версия 10. Проверены Unicode,
CRLF, совпадение внутри длинной строки, файл с нулевым байтом и
пагинация поиска. Краткие итоги проверок S4-88 также прошли тесты
для версии 11. Хеши 414 запросов из сохранённых журналов OMS-22–25
совпали.

Ruff прошёл. Прошли 227 целевых тестов, 2 пропущены. Расход API $0.
Код подготовлен в `codex/s4-89-search-read-hints`. Отчёт и пример
чтения сохранены на SSD в `checks/s4-89-search-read-hints/verification.json`.
Перед установкой рабочая OMS была на `f5bf5449e`.

## Публикация и установка

Единственный полный прогон выпуска `0686777` дал 6 968 прошедших тестов,
176 пропусков и один сбой теста возобновления чата
`test_failed_mode_rebuild_moves_session_to_explicit_resume`. Тест прошёл
при отдельной последовательной перепроверке в той же копии.
Отчёт `release-verification-rechecked.json` сохраняет оба результата.

21.11.2026 Сергей подтвердил публикацию `0686777`, затем отдельно слияние
и установку [PR №143](https://github.com/Serg10011/oh-my-symphony/pull/143).
Обе рабочие копии обновлены до `ac297f7d3`. Установщик принял сохранённый
отчёт, выполнил проверки конфигурации и перезапустил службу OMS. Проверки
завершились без ошибок. Установщик предупредил, что `symphony` отсутствует
в `PATH` оболочки. Служба использует заданный абсолютный путь.

После перезапуска доска ответила, в очереди было 0 запусков и 0 повторов.
Сверены 30 карточек, 17 сессий и настройки Sol 6.2 High соло в режиме
«Экономия». На установленном коде поиск снова вернул диапазон для чтения
41 строки примера OMS-25, продолжение открыло следующий фрагмент.
Расход API $0. Журнал установки и снимок проверки сохранены на SSD в
`checks/s4-89-search-read-hints/installation.log` и
`checks/s4-89-search-read-hints/live-verification.json`.
