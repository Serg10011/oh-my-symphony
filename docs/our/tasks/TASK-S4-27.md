## 1. `ours/bin/deliver push <ID>` — доставка

Запуск: `ours/bin/deliver push <ID> [--root DIR] [--main DIR] [--gh PATH]` (`--root` — папка досок, умолчание `pc.DEFAULT_ROOT`; `--main` — основная папка форка, умолчание — как `post_merge.default_main`; `--gh` — путь к `gh`, умолчание — поиск в `PATH`). Коды выхода: 0 — доставлено, 1 — отказ (ничего не изменено), 2 — ошибка. Вывод — по-русски. Всё внешнее (`gh`, адрес удалённого репозитория для пуша и `ls-remote`) — через `Ops`, как в `post_merge.py` и `inbox_runner.py`: в тестах удалённый репозиторий — локальный «голый» (`bare`) репозиторий, `gh` — подмена.

### 1.1 Доска, карточка, раздел `[delivery]`

- `<ID>` — строго `<PREFIX>-<N>` (подзадача `<ЗАДАЧА>-k` — отказ «подзадача доставляется в составе задачи»). Доска — единственная папка под `--root`, у которой `[project] id_prefix` = `<PREFIX>` (`pc.other_projects`); не нашлась или их несколько — отказ. Конфигурация — `pc.load_project`.
- Новый раздел `project.toml` **`[delivery]`**: `repo` (строка `владелец/имя`, только `[A-Za-z0-9._-]`), `base` (строка). Раздел необязателен; без него `deliver` отказывает «нет раздела [delivery]». Загрузчик проверяет форму и неизвестные ключи, как у других разделов. `deliver` дополнительно отказывает **всегда**, если владелец `cskwork` (без учёта регистра; константа в коде), и если `base` ≠ `[project] base_branch` (иначе проверка «`our-main` не сдвинулся» шла бы не по той ветке). В заготовке `project-new` — раздел закомментированным примером по-русски.
- Карточка `<доска>/kanban/<ID>.md` в статусе `Human Review`. Вид: **карточка-задача** (`integrate.is_task_card`) или **обычная**; подзадача (`integrate.is_subtask`) — отказ.
- Блокировка карточки — `check.try_lock` (ждать до 5 с; занята — отказ «идёт проверка карточки»).
- Уже доставлена (`<доска>/.ours-state/<ID>.delivered.json` есть и в нём есть PR) — отказ со ссылкой на PR. Чтобы доставить заново, запись удаляет человек (написать это в памятке).

### 1.2 Источник и «зелёная проверка»

Всё — в репозитории кода доски (`[project] repo`, клон).

- **Источник:** карточка-задача — конец `integration/<ID>` (префикс — `[integration] branch_prefix`); обычная — конец `symphony/<ID>`.
- **Отметка (правка `check.py`).** Сейчас событие `hook pass` в `check.log` дерева не несёт, а `<ID>.pass.json` у обычной карточки никто не забирает и после следующего провала остаётся устаревшей — надёжной записи нет. Поэтому в `_hook_checked` в событие `pass` добавляются поля `tree` и `head` (те, что уже считаются для `.pass.json`; нет их — полей нет). `.pass.json` не менять.
- **Поле `tests` в `hook pass` — всегда.** Сейчас у обычной карточки при полном прогоне поля `tests` в событии нет (оно есть только у карточки-задачи и при пропусках). В событии `hook pass` поле `tests` = `full`, если `test.sh` действительно прогнан; `skipped-docs` — как сейчас. События `gate` не менять: на отсутствие поля у полного прогона опираются существующие тесты `test_light_path.py`.
- **Зелёная проверка есть**, если среди событий карточки в `check.log` последнее **решающее** (`hook pass`, `hook rollback:*`, `gate fail`) — это `hook pass`, его `tree` равно дереву конца источника (`git rev-parse <конец>^{tree}`) **и `tests` = `full`** (решение архитектора: лёгкий путь — не зелёная проверка для доставки, S4-16 п. 4: полный прогон перед доставкой обязателен независимо от `doc_paths`, а `post-merge` после слияния одних документов тестов не гоняет). Иначе отказ с причиной: «нет проверки с деревом (событие до S4-27)», «после проверки был откат / провал шлюза», «дерево ветки не то, что прошло проверку», «проверка шла лёгким путём: полный прогон перед доставкой — S4-28».
- Заодно (мелочь в `run_checks`): ветка «запись „влито“ не совпала по дереву» перезаписывает `mark` целиком (`mark = {"tests": "full", …}`) и теряет поля `baseline_*` из S4-25 — дополнять, а не перезаписывать.
- Карточка-задача дополнительно: `integrate.final_path` есть, `task` = ID, `branch` = `integration/<ID>`, `integration_commit` = конец источника. Почему дерево сравнивается с `integration/<ID>`: после `finish_task` рабочая копия карточки-задачи стоит на конце интеграционной ветки, а Verify и Document пишут только в папку доски (исключения `worktree-exclude`); если агент изменил файлы репозитория, деревья разойдутся — это отказ «в ветке карточки-задачи правки после итоговой проверки».

### 1.3 `our-main` не сдвинулся

- **Клон не отстаёт от GitHub:** `git ls-remote <адрес> refs/heads/<base>` = `refs/heads/<base>` клона, иначе отказ «клон отстаёт от GitHub: сначала ours/bin/post-merge» (замеры базы и проверки идут по клону).
- **Не сдвинулся:** карточка-задача — `our_main` из `.final.json` = концу `<base>`; обычная — конец `<base>` — предок конца источника.
- Сдвинулся — отказ «`our-main` ушёл вперёд после зелёной проверки (<sha> → <sha>): повторная проверка будет в S4-28, пока доставка вручную». Ничего не меняется.
- **D = конец источника.**

### 1.4 Пуш

- Ветка на GitHub уже есть (`git ls-remote <адрес> refs/heads/deliver/<ID>` не пусто) — отказ, кроме случая «продолжить» (п. 1.6).
- Адрес — только `https://github.com/<repo>.git` из `[delivery]`, не `origin` клона. Ветка — строго `deliver/<ID>` (проверка в коде: никогда `main`, `our-main` и вообще никогда `base`). Команда: `git -C <клон> push <адрес> <D>:refs/heads/deliver/<ID>` — без `--force` и без `+` в refspec. Учётные данные — через `gh` (`-c credential.helper= -c credential.helper=!<gh> auth git-credential`), `GIT_TERMINAL_PROMPT=0`; токены не попадают ни в адрес, ни в журнал, ни в файлы.

### 1.5 PR и записи

- **Сначала — нет ли уже PR** (решение архитектора; случай «PR создан, ответ потерян»): `gh pr list --repo <repo> --head deliver/<ID> --state open --json number,url,headRefName,baseRefName`. - Иначе — `gh pr create --repo <repo> --base <base> --head deliver/<ID> --title "<ID>: <название карточки>" --body-file <временный файл>`. Название — из шапки карточки, одной строкой, без управляющих символов, до 120 знаков. Описание: раздел `## As-Is -> To-Be Report` карточки (если его нет — строка «отчёта нет»); у карточки-задачи — ещё список подзадач (строки `## Plan Accepted`); итог проверки: коммит D, источник, `our-main`, «повторной проверки не было». Всё вместе не больше 60 000 знаков (дальше — обрезка со строкой «обрезано»). Текст карточки пишет агент — только аргументами и файлом, без оболочки.
- После пуша сразу — запись `<доска>/.ours-state/<ID>.delivered.json`: `id`, `kind` (`task` / `card`), `source` (ветка), `source_commit`, `source_tree`, `commit` (D), `our_main`, `recheck: false`, `repo`, `base`, `branch` (`deliver/<ID>`), `pr` (номер и адрес; до создания PR — `null`), `at`. Запись атомарная.
- После PR: раздел `## Delivery` в карточке (`check.append_note`: PR, D, источник, `our-main`, «повторной проверки не было»), событие `delivered` в `check.log` (`"mode": "deliver"`), `git fetch origin` в основной папке — только если `origin` основной папки — тот же репозиторий, что `[delivery] repo` (сравнение — одной функцией, `post_merge.normalize_url`, не копией). Карточка остаётся в `Human Review`.
- Отказы и ошибки — событие `refused` / `error` с причиной.
