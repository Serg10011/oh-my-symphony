## Зачем

Решение архитектора (`docs/our/DECISIONS.md`, запись «Решения архитектора по REPORT-17», п. 9 и шаг 3 порядка реализации): запрет `ours/**` для проекта `oms` снять, но сохранить защищённый «контур контроля» — файлы, которые проверяют работу агента и задают его права. Контур и права меняют только задачи, запущенные человеком (локальный Claude Code), не карточки конвейера. После этого мелкие задачи (документы, промпты, новые тесты) можно пускать карточками на доску `oms`.

Сейчас запрет — встроенное умолчание `DEFAULT_FORBIDDEN_PATHS` в `ours/hooks/check.py` (`"ours/**"`), его нельзя отключить из `project.toml` (`forbidden_paths` только добавляет). Агент не может править ничего в `ours/`.

## Решение (принято чатом этапа, реализуй именно так)

Схема «запрещено по умолчанию + явный список разрешённого + неснимаемый контур»:

1. **Умолчание не меняется:** `ours/**` по-прежнему запрещён для всех проектов.
2. **Новый ключ `[checks] allow_paths`** (список шаблонов, необязательный, по умолчанию пустой). Путь, подходящий под `allow_paths`, освобождается **только от шаблона `ours/**`**. От остальных запретов (`WORKFLOW.md`, `.github/**`, `.git/**`, `.env`, `.env.*`, `**/*.pem`, `**/*.key` и `[checks] forbidden_paths` проекта) освободить нельзя.
3. **Каждый шаблон `allow_paths` должен начинаться с `ours/`**, иначе ошибка конфигурации `config: …` (как для других неверных значений в `load_config`). Шаблон не должен быть пустым.
4. **Неснимаемый контур** — константа `CONTROL_CONTOUR` в `check.py`: `("ours/hooks/**", "ours/bin/**", "ours/templates/**")`. Путь под контур запрещён всегда, даже если подходит под `allow_paths` (например, при ошибке `allow_paths = ["ours/**"]`). Так новые файлы управления (хук вливания, `deliver`, и т. п.) защищены автоматически, без правки списка. В контур входят `check.py`, `worktree.py`, `project_config.py`, `inbox_runner.py`, `post_merge.py`, `WORKFLOW.md.tmpl`, `ours/bin/*`, а также `summarize.py`, `project-new`, `project-doctor`, `project-render`, `project-launchd` (они пишут права/`WORKFLOW.md`/базу — это сознательное расширение списка архитектора; опиши его в DECISIONS).
5. Итог для `oms` (значения пропишет Сергей в `project.toml` вне репозитория, не ты): `allow_paths = ["ours/prompts/**", "ours/README.md", "ours/tests/**"]`. То есть агент сможет править промпты, `ours/README.md` и добавлять новые тесты в `ours/tests/` (изменение существующих тестов по-прежнему запрещено проверкой «существующие тесты» — она уже есть). Всё остальное в `ours/` — запрещено.

Реализация `forbidden_violations` (подсказка, можно иначе, но смысл тот): путь нарушает запрет, если подходит под контур; либо под любой запрещённый шаблон, кроме `ours/**`; либо под `ours/**` и не подходит под `allow_paths`. Проверка идёт по всем изменённым путям, как сейчас (включая переименования: старый и новый путь, как сейчас делает `changed_paths`). Формулировка нарушения `forbidden path changed: <путь>` остаётся (существующие тесты на неё не должны ломаться); для контура можно добавить пояснение в конце, но префикс сохрани.

`project_config.py`: добавь `"allow_paths": (list, False)` в схему `checks`. Проверь, как схема проверяет элементы списков (строки) — используй тот же способ. Если `project_config.py` проверяет и содержимое `[checks]` где-то ещё (например, в `project-render`), согласуй.

## Тесты (новые, в новом файле `ours/tests/test_check_contour.py`; существующие тесты не менять)

Возьми из `ours/tests/test_check.py` готовые вспомогательные средства (фикстура `env`, функции создания репозитория и вызова проверки): импортируй или повтори минимально — выбери проще и скажи в PR. Все подпроцессы со скриптами — только через `sys.executable`; тесты должны проходить и в среде `env -i HOME="$HOME" PATH=/usr/bin:/bin:/usr/sbin:/sbin`.

- Без `allow_paths`: изменение `ours/prompts/x.md` — нарушение (поведение как раньше).
- С `allow_paths = ["ours/prompts/**", "ours/README.md", "ours/tests/**"]`: `ours/prompts/x.md`, `ours/README.md`, новый `ours/tests/test_new.py` — без нарушений.
- С тем же `allow_paths`: `ours/hooks/check.py`, `ours/hooks/worktree.py`, `ours/hooks/project_config.py`, `ours/templates/WORKFLOW.md.tmpl`, `ours/bin/inbox-runner`, `ours/bin/post-merge`, `ours/bin/deliver` (даже если такого файла ещё нет — новый файл), `ours/hooks/integrate_new.py` (новый, неизвестный) — нарушения.
- Ошибочный `allow_paths = ["ours/**"]`: контур всё равно запрещён (`ours/hooks/check.py` — нарушение), а `ours/prompts/x.md` разрешён.
- `ours/prompts/secret.pem` и `ours/prompts/.env` при `allow_paths = ["ours/**"]` — нарушения (освобождение только от `ours/**`).
- Проектный `forbidden_paths = ["ours/prompts/locked/**"]` при `allow_paths = ["ours/prompts/**"]`: `ours/prompts/locked/a.md` — нарушение.
- Переименование файла из контура в разрешённую зону (`git mv ours/hooks/check.py ours/prompts/check.py`) — нарушение (по старому пути); переименование разрешённого файла в контур — нарушение (по новому).
- Неверный `allow_paths`: шаблон `"src/**"`, пустая строка, не список, не строки — отказ конфигурации с понятным сообщением.
- Охранный тест: перебери все файлы репозитория (`git ls-files ours/hooks ours/bin ours/templates`) — каждый из них нарушение при `allow_paths = ["ours/**"]` (ничто в контуре нельзя открыть списком).
- `ours/tests/test_check.py` и остальные существующие тесты проходят без изменений.
