# S4-62 — рабочая API-разработка на браузерной доске

Подключи согласованную API-команду к конвейеру в браузере: пользователь
задаёт цель в карточке, подтверждает назначенные модели и получает
изменённый код с проверками и понятным результатом для приёмки.
Применение изменений и запуск проверок должны выполняться средой конвейера,
без ручной сборки патча архитектором. Ведущий сам организует работу;
проверяющему доступны все актуальные изменения, включая новые тесты.

Работа идёт в изолированной копии выбранного проекта. Сохрани существующий
контур Anthropic, его настройки и данные. Выполнение, остановка и расходы
по участникам видны пользователю; неизвестные расходы не превращаются в ноль.
Платное выполнение начинается после подтверждения конкретного назначения,
а приёмка и слияние остаются за человеком.

## Четвёртая итерация — среда полного прогона, 05.11.2026

По «Го дальше» проверены текущие средства, старое требование отдельной
среды в ARCHITECTURE.md §13 и поведение четырёх сетевых профилей Codex.
Собственные безопасные пробы подтвердили: разрешение local binding
одновременно позволяет обращаться к другому местному серверу Mac.
Поэтому этот флаг не заменяет отдельную сеть тестового окружения.
Настоящие службы, ключи и API в пробах не используются.

Подготовлено предложение для согласования с Сергеем:

- Отдельная Linux ARM64 VM через Lima/VZ, папка /Volumes/ssd/symphony-checks.
  Внешний диск APFS, свободно около 1,3 ТиБ. Системный диск в ходе замеров
  имел 7,9–9,8 ГиБ свободного места; поэтому образ туда не планируется.
- 2 виртуальных CPU, 4 ГиБ памяти во время работы, виртуальный диск 24 ГиБ;
  на первую установку, образы и данные разрешение запрашивается до 32 ГиБ.
  Физическая память Mac — 16 ГиБ. Без автоматического запуска при входе.
- Plain mode, без общих папок с Mac, проброса SSH-agent и автоматической
  публикации тестовых портов. API-ключи и GitHub-доступ остаются на Mac.
  Внутрь передаются копия конкретного кандидата и доверенные проверки.
- Во время подготовки образа допускается загрузка проверенных зависимостей;
  запуск кода задачи должен иметь отдельную сеть с собственным loopback,
  без маршрута к Mac/интернету. Plain mode сам по себе сеть не отключает.
  Работоспособность и запреты необходимо подтвердить до платной карточки.
- Полный набор и база проверяются в одинаковой версии среды. Старый
  macOS baseline не применяется к Linux. Мак-специфичные пропуски должны
  быть видны; Linux-проверка не выдаётся за проверку поведения macOS.

Это предложение по инфраструктуре, **ещё не принятое Сергеем**. Lima не
установлена, новая VM не создана, имеющаяся Windows 11 остаётся выключенной.
Разрешение на эту среду не будет разрешением на платную API-задачу,
слияние PR или обновление действующего конвейера. Реальный монтаж среды
и её проба требуют подтверждения этой архитектурной развилки по AGENTS.md.
Назначение Astra/max прежнее; новые чаты и субагенты не создавались.
