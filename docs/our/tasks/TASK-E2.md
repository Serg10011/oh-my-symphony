## Зачем

Одно правило решает и «перемерять ли базу после слияния» (`post-merge`), и «верить ли старому замеру» (`check.py`, S4-25). Сейчас оно одно на все проекты и рассчитано на Python (`tests/`, `test_*.py`, `conftest.py`, `pyproject.toml`…). ## 1. Раздел `[baseline]` в `project.toml`

- `paths` — список шаблонов путей от корня репозитория кода, **тот же синтаксис, что у `[checks] forbidden_paths`** (одна функция разбора шаблонов на всё; если для этого её нужно перенести в `project_config.py` — перенеси, `check.py` берёт её оттуда; без копий).
- **Раздела нет — правило прежнее**, ровно как сейчас (`pc.BASELINE_RULE`: префиксы, файлы, имена). Доска `oms` раздела не получает, её поведение не меняется. На это опираются существующие тесты (`test_post_merge.py::...matches("doctor", …)`, `test_baselines.py::test_post_merge_takes_the_rule_from_project_config` — `post_merge.RULES["doctor"] is pc.BASELINE_RULE`); их не менять.
- **Раздел есть — он заменяет правило целиком** (не дополняет): проект на другом языке не наследует питоновских шаблонов.
- Проверка загрузчиком: непустой список строк; каждый шаблон относительный, без `..`, без ведущего `/`, разбирается функцией шаблонов; неизвестный ключ — ошибка, как в других разделах.
- **Согласованность с `[checks] test_globs`** (решение архитектора): если `[baseline]` задан, каждый шаблон из `test_globs` (явных из `project.toml` или `check.DEFAULT_TEST_GLOBS`, если их нет) обязан **буквально** присутствовать в `[baseline] paths` — иначе ошибка загрузки с перечнем недостающих. Причина: файл, защищённый как тест, обязан и вызывать перемер, и обесценивать старый замер. Без раздела `[baseline]` этой проверки нет (прежнее правило). Умолчание `test_globs` — в одном месте (если для проверки в загрузчике его нужно перенести из `check.py` в `project_config.py` — перенеси, `check.py` берёт оттуда).
- Одна функция «меняет ли этот путь то, что измеряют тесты» для данного проекта (например `pc.affects_baseline(path, project)` или «правило проекта» объектом) — ею пользуются оба места ниже.

## 2. Где правило применяется

- **`check.py`, поиск замера-предка** (`effective_baseline`, S4-25): файлы между записью и точкой ответвления проверяются правилом **этой доски** (из её `project.toml`), а не общим.
- **`post-merge`, решение «нужен ли `project-doctor`»** (`classify`): для каждого проекта — правило этого проекта. Если `project.toml` проекта не читается — проект получает отказ с причиной (как другие проблемы проекта в `post-merge`), а не молчаливое «перемерять не нужно».
- Важно (записать в документы): `post-merge` обслуживает только проекты, чей репозиторий — клон того же репозитория, что основная папка форка (`find_projects`). Для доски EVE (другой репозиторий) правило сейчас работает только в `check.py`; перемер базы EVE после слияний в её `main` не автоматизирован — это часть доставки EVE (не в этой задаче; проба EVE — без доставки, база во время пробы не двигается). **Решение архитектора:** пока нет доставки EVE, после изменений базовой ветки EVE чат этапа запускает `project-doctor` доски EVE вручную.

## 3. Заготовка `project-new`

Раздел закомментированным примером по-русски: что значит правило и где используется; что без раздела действует питоновское правило (перечислить его словами); что с разделом все шаблоны `[checks] test_globs` обязаны быть в `paths`; пример для Vitest (решение архитектора: выровнен с `DEFAULT_TEST_GLOBS`; `vitest.*` — конфиг, файлы подготовки, workspace):

```toml
# [baseline]
# paths = ["tests/**", "**/*.test.ts", "**/*.test.tsx", "**/*.spec.*", "vitest.*",
#          "vite.config.*", "package.json", "package-lock.json", ".nvmrc", "tsconfig*.json"]
```

**Уточнение чата этапа (по коду):** в `DEFAULT_TEST_GLOBS` есть ещё `**/test_*.py`, `**/*_test.py`, `**/*_test.go`. Поэтому пример выше проходит проверку согласованности только вместе с явными шаблонами тестов Vitest; в заготовке рядом с примером — строка:

```toml
# и в [checks]: test_globs = ["tests/**", "**/*.test.ts", "**/*.test.tsx", "**/*.spec.*"]
#   (иначе к paths нужно добавить и питоновские/Go-шаблоны умолчания: **/test_*.py, **/*_test.py, **/*_test.go)
```
