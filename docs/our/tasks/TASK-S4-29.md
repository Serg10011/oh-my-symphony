## Зачем

Сергей хочет следить за задачами очереди и отвечать на вопросы с телефона, когда он не у компьютера. В `/config` у него уже включены автоподключение Remote Control для всех сессий и push-уведомления. Не хватает двух вещей: сессия должна называться кодом задачи (иначе в списке сессий на телефоне — случайное имя), и Claude Code должен сам присылать push по итогу или с вопросом.

## 1. `terminal_command`

Строка для Терминала получает `--remote-control <код>` (код — уже проверенный `valid_code`, `[A-Za-z0-9-]`; через `shlex.quote`). Ключ — **перед** текстом задания, сразу после `--model` / `--effort`: у `--remote-control` имя необязательное, поэтому имя пишем явно, чтобы следующим аргументом не стал текст задания. Остальное без изменений: `cd <рабочая копия> && claude --model … [--effort …] --remote-control <код> "<текст>"`.

## 2. `TASK_PROMPT`

К строке `Выполни задание из файла {path}` добавить в ту же строку (те же двойные кавычки): «Когда закончишь (ветка запушена, PR создан) или упрёшься в вопрос к Сергею — пришли ему push-уведомление с кратким итогом или вопросом, если такой инструмент доступен.» Без символов, опасных внутри двойных кавычек в zsh/bash (`"`, `$`, `` ` ``, `\`, `!`) — проверь утверждением, как сейчас для пути. Поиск процесса задачи по пути задания (закрытие окна после `.merge`) должен работать по-прежнему — проверь тестом.
