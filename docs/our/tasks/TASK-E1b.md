## Что выяснено по документации Claude Code (28.10.2026, проверено чатом этапа)

- **Порядок выбора учётных данных** (раздел Authentication → Authentication precedence): `ANTHROPIC_AUTH_TOKEN` → `ANTHROPIC_API_KEY` → **вывод `apiKeyHelper`** → `CLAUDE_CODE_OAUTH_TOKEN` → … → вход по подписке (`/login`). То есть `apiKeyHelper` главнее входа по подписке: при заданном помощнике ходы оплачиваются ключом, иначе — подпиской.
- `apiKeyHelper` — настройка «Any file»: её можно передать файлом через `claude --settings <файл>` (уровень «command line», выше пользовательских и проектных файлов). Помощник — команда для `/bin/sh`, печатает ключ на stdout одной строкой печатных ASCII-символов и выходит с кодом 0; при ошибке запросы падают с «Your apiKeyHelper script is failing». По документации вывод помощника отправляется в заголовке запроса; попадает ли он в окружение команд агента, документация прямо не говорит — **проверить боем** после 30.10 (п. 6).
- Правила `permissions.deny` вида `Read(//<абсолютный путь>)` действуют на файловые инструменты Claude **и на распознанные файловые команды Bash** (`cat`, `head`, `tail`, `sed`, `tee`, перенаправления), но **не на произвольные подпроцессы** (скрипт Python или Node, который сам открывает файл). Для защиты на уровне ОС нужна песочница Claude Code (`sandbox.filesystem.denyRead`) — в этой задаче её **не включать** (меняет права всех команд агента; отдельное решение).
- «Credit balance is too low» — сообщение при кончившемся кредите организации Console.

## 1. Раздел `[billing]` в `project.toml`

- `mode` — `"plan"` (умолчание, всё как сейчас) или `"api"`.
- `api_key_file` — абсолютный путь к файлу с ключом; обязателен при `mode = "api"`. Загрузчик (`validate_project`) проверяет только форму: абсолютный, без `..`, только `[A-Za-z0-9._/-]` (путь попадает в команду помощника для `/bin/sh`), неизвестные ключи — ошибка. Наличие и права файла загрузчик **не** проверяет (иначе пропавший файл ломал бы каждый хук доски) — это делают `project-render` и `project-doctor` (п. 2, 4).
- В заготовке `project-new` — раздел закомментированным примером по-русски: что значит каждый режим, что ключ берётся в Console (рабочее пространство доски, свой потолок трат), как создать файл с правами 600, как переключить режим обратно.

## 2. Сборка (`project-render` / `template_values`)

**Режим `api`:**

- Проверка файла ключа (иначе `ProjectError`, `WORKFLOW.md` не пересобирается): существует, обычный файл (не ссылка), владелец — текущий пользователь, права без доступа группе и остальным (`mode & 0o077 == 0`), размер до 1 КБ, лежит **вне** репозитория кода (`[project] repo`), вне папки доски, вне корня рабочих копий (`default_workspace_root`) и вне основной папки форка.
- **Папка ключа — только для ключей** (решение архитектора; образец — `~/.symphony-keys/`): правило `deny` закрывает всю папку, поэтому она не может быть домашней папкой и не может содержать (быть предком или совпадать) репозиторий кода, папку доски, корень рабочих копий или основную папку форка — иначе правило закрыло бы агенту его собственную работу. Нарушение — `ProjectError`. Права папки — без доступа группе и остальным (`700`).
- Файл настроек `claude`: `<доска>/claude-settings.json` (атомарно, права 600):
  - `"apiKeyHelper": "/usr/bin/tr -d '[:space:]' < '<api_key_file>'"` — печатает ключ без пробелов и перевода строки;
  - `"permissions": {"deny": ["Read(//<папка ключа без первого />/**)"]}` — вся папка ключей: файловые инструменты и `cat`/`head`/`tail` агента не читают ни один ключ.
- Команда `claude` получает `--settings <доска>/claude-settings.json`.
- В `WORKFLOW.md`, раздел `agent:` — `quota_exhausted_state: needs_human` и `quota_exhausted_note` с текстом: «API-кредит исчерпан или ключ недоступен (apiKeyHelper) — переключи доску на подписку: в project.toml раздел [billing] mode = "plan", затем ours/bin/project-render <имя>. Остальные карточки ждут: служба не берёт новые, пока WORKFLOW.md не пересобран. Автоматически доска на подписку не переключается.» (Остановку доски после первой такой карточки делает ядро — E1a; пересборка `WORKFLOW.md` её снимает.)

**Режим `plan`:** ни `--settings`, ни ключей `quota_exhausted_*` (поведение как до E1a: пауза); если в папке доски остался `claude-settings.json` — удалить его при сборке (иначе запутает). Отрисованный `WORKFLOW.md` доски без `[billing]` побайтно совпадает с прежним (тест).

Служба перечитывает `WORKFLOW.md` на каждом цикле: после `project-render` новый режим действует со следующего хода (проверь это утверждение по `post_merge.py` / коду ядра и запиши в документы, если так).

## 3. Защита ключа: «ключ в диффе» (все доски, в любом режиме)

- **`check.py`, быстрая проверка** (вместе с запрещёнными путями, до тестов): в **добавленных** строках изменений относительно базы — закоммиченных, в индексе, не в индексе и в неотслеживаемых файлах (те же пути и исключения, что у `changed_paths` / `STAGE_PATHSPEC`) — ищется `sk-ant-[A-Za-z0-9_-]{20,}`. Найдено — отказ: «в добавленных строках найден ключ API Anthropic (sk-ant-…): <путь>:<номер строки>; сама строка не выводится». Двоичные файлы пропускаются. Текст строки не попадает ни в отчёт, ни в `## Check Failure`, ни в `check.log`.
- **`deliver push`**: перед пушем — та же проверка по добавленным строкам `git diff <base>..<D>`, а также по заголовку и описанию PR (описание собирается из карточки, её пишет агент) → отказ, ничего не пушится.
- Одна функция поиска для обоих (в `check.py`), без копий.
- **В тестах и документах ключ-образец не писать буквально** (иначе первая же карточка, тронувшая такой файл, получит отказ): в тестах собирать строку во время выполнения (`"sk-" + "ant-" + "x" * 30`), в документах — только `sk-ant-…`.

## 4. `project-doctor`

В режиме `api` — те же проверки файла и папки ключа, что в п. 2, и запуск команды помощника (`/bin/sh -c`, таймаут 10 с): вывод — одна строка вида ключа Anthropic; сам вывод нигде не печатается (PASS/FAIL с причиной). Запроса к API нет (он тратил бы кредит). В режиме `plan` — строка «оплата: подписка».

**В обоих режимах** (решение архитектора) — FAIL, если `ANTHROPIC_API_KEY` или `ANTHROPIC_AUTH_TOKEN` есть в окружении службы (раздел `EnvironmentVariables` файла автозапуска доски `<доска>/launchd.plist`, если он есть) или в окружении, в котором запущен сам `project-doctor`. Причина: они главнее `apiKeyHelper` и входа по подписке — в режиме `plan` ходы тихо пошли бы на API, в режиме `api` — с чужого ключа мимо потолка трат. В выводе — только имя переменной и где она найдена, без значения. (Сам `project-launchd` эти переменные не пишет — проверь и закрепи тестом.)
